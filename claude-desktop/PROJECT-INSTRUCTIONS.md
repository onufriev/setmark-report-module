# Product Compiler — инструкции для Claude Desktop

Работай только как Product Compiler и следуй `PRODUCT-COMPILER.md`. Не придумывай недостающие требования и не оставляй области пустыми.

Подтверждённым считается только то, для чего есть проверяемая выдержка из зарегистрированного снимка источника или явный ответ Product Manager. Если ответа нет, создай `NEEDS_INPUT`, задай один вопрос и остановись.

## Необязательные критики

Критики находятся в `critics/agents/`. Они не запускаются автоматически и не являются обязательным gate.

Перед завершением значимого этапа один раз спроси:

> Хотите подключить критика для дополнительной проверки этого этапа?

При согласии прочитай `critics/PROCESS-INTEGRATION.md`, предложи только релевантных критиков и запусти только выбранных. Сохрани отчёты в `critics/reports/`. Не исправляй требования или прототип по замечаниям без отдельного решения Product Manager.

При отказе продолжай основной процесс. Отказ не блокирует этап, не считается риском и не требует повторного вопроса на текущем этапе. Прямой запрос Product Manager «запусти Nora», «проверь Kane» или аналогичный считается явным согласием на конкретного критика.

Если среда Claude Desktop/Cowork обнаруживает project skills из `.claude/skills/`, используй их. Если skills не обнаружены, используй соответствующие универсальные инструкции из `critics/agents/`; результат должен быть одинаковым.

## Основной процесс

До визуального прототипа:

- проверь каждую область из `internal/domain-catalog.json`;
- явно зафиксируй подтверждённое требование, подтверждённую неприменимость или `NEEDS_INPUT`;
- закрой все области gate `VISUAL_PROTOTYPE`;
- выбери источник UI;
- зафиксируй baseline через `tools/commit_requirements.py`;
- получи отдельное утверждение отчёта `PRODUCT_DEFINITION`.

Для рабочего прототипа отдельно зафиксируй стек и источник данных. Реализация обязана иметь манифест, полную инструкцию запуска, настройки, наполнение и сброс данных, health-check и проверяемый основной сценарий.

Не редактируй `project-state.json`. Не создавай phase review вне `reports/`. Не вызывай `register_phase_review.py` напрямую.

После регистрации отчёта запусти `tools/present_phase_review.py`, вставь напечатанные ссылки в ответ, первой покажи ссылку на PDF, затем вызови `tools/mark_phase_review_shown.py` и остановись. Переход разрешён только отдельным сообщением Product Manager.

# Руководство Product Manager

Product Manager:

1. объясняет проблему, пользователей и желаемый результат;
2. определяет границы текущей версии;
3. уточняет основные действия и продуктовые правила;
4. отвечает на действительно блокирующие продуктовые вопросы;
5. может оставить остальные вопросы открытыми;
6. выбирает, нужен ли визуальный или рабочий прототип;
7. просматривает контрольный отчёт и отдельно разрешает переход.

Product Manager не обязан выбирать production-архитектуру, API, хранилище,
очереди, развёртывание, резервирование и внутренние эксплуатационные механизмы.
Product Compiler не должен предлагать такие решения для подтверждения.

Если выбран рабочий прототип, Product Manager подтверждает его стек и источник
данных как условия эксперимента. Это не выбор будущей production-архитектуры.

Служебные идентификаторы доказательств не предназначены для чтения требований.
Они используются инструментами проверки и показываются только при диагностике.

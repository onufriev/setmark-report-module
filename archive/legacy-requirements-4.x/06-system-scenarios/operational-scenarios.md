# Эксплуатационные сценарии жизненного цикла

## REQ-DEC-150. Решение Product Manager

**Область:** operationalScenarios
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-165
**Применимость:** MVP1

После установки или обновления Set Mark до версии с MVP пользователь получает новую функциональность в текущем Журнале нарушений независимо от версии SetCentrum. При обновлении только SetCentrum и старой версии Set Mark ничего не появляется; система не показывает неработающую точку входа или заглушку. Несовпадение версий между продуктами не изменяет существующие функции Журнала нарушений.

### Проверка
Реализация соответствует решению PM-DEC-165.
## REQ-DEC-121. Решение Product Manager

**Область:** operationalScenarios
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-136
**Применимость:** MVP1

Настройка подключения True API обязательна до первого получения данных и ввода Мониторинга маркировки в эксплуатацию для соответствующего ИНН. Отсутствие настройки не блокирует существующую функциональность Журнала нарушений.

### Проверка
Реализация соответствует решению PM-DEC-136.
## REQ-DEC-116. Решение Product Manager

**Область:** operationalScenarios
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-131
**Применимость:** MVP1

После поставки версии Set Mark с функциональностью MVP пользователь работает с ней в интерфейсе текущего Журнала нарушений. Появление отдельной визуализации Set Mark в SetCentrum не является эксплуатационным сценарием MVP.

### Проверка
Реализация соответствует решению PM-DEC-131.
## REQ-DEC-022. Решение Product Manager

**Область:** operationalScenarios
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-022, PM-DEC-136
**Применимость:** MVP1

Для функции внутри Set Mark применяются следующие эксплуатационные сценарии жизненного цикла: у функции нет отдельной установки, ручного включения и развёртывания — она поставляется как часть Set Mark; при этом для ввода Мониторинга в эксплуатацию требуется пользовательская настройка подключения True API по каждому ИНН; обновление и откат выполняются штатными средствами Set Mark; резервное копирование, восстановление, миграция и вывод из эксплуатации выполняются на уровне Set Mark и его данных; после перезапуска функция автоматически продолжает обработку сохранённых событий; при недоступности сети или источника отображаются свежесть и полнота данных, а накопленные события обрабатываются после восстановления; частичная недоступность не скрывается — пользователю показываются доступные данные и влияние сбоя; замену интеграции или зависимого компонента выполняет Set Mark, функция продолжает работать при сохранении установленного контракта данных; отдельный назначенный администратор для первичной настройки не требуется; эксплуатационные сбои функции не влияют на продажи и проверку кодов.

### Проверка
Реализация соответствует решению PM-DEC-022.
## Сценарии, которые нельзя игнорировать

Для каждого пункта необходимо подтвердить применимость или явно зафиксировать «не применимо»:

1. Первая установка.
2. Первичная настройка.
3. Развёртывание в новом окружении или подразделении.
4. Обновление приложения или компонентов.
5. Неуспешное обновление и откат.
6. Резервное копирование.
7. Восстановление данных и конфигурации.
8. Перезапуск после аварийного завершения.
9. Недоступность сети.
10. Недоступность внешнего сервиса.
11. Частичная недоступность системы.
12. Перенос или миграция данных.
13. Замена зависимого компонента или интеграции.
14. Вывод из эксплуатации.
## REQ-DEC-100. Условие появления визуализации после обновления

**Область:** operationalScenarios
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-115, PM-DEC-131
**Применимость:** Следующий этап

На следующем этапе визуализация Set Mark появляется в SetCentrum после установки Set Mark либо после обновления уже установленного Set Mark до актуальной совместимой версии, а также в предусмотренном требованиями демонстрационном режиме. Отдельное ручное включение функции администратором после выполнения условий этапа не требуется. В MVP пользователь работает в интерфейсе текущего Журнала нарушений.

### Проверка
В MVP отдельная визуализация в SetCentrum отсутствует; на следующем этапе её доступность определяется условиями установки, демонстрационного режима, страны, лицензии и прав пользователя.

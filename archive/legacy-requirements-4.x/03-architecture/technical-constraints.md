# Технические ограничения прототипа

## REQ-DEC-180. Решение Product Manager

**Область:** technicalConstraints
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-195
**Применимость:** MVP1

Мониторинг не добавляет синхронных вызовов в процесс проверки марки и продажи. Отправка данных, получение ЧЗ, сопоставление и расчёт агрегатов выполняются асинхронно с отдельными очередями, исполнителями и лимитами подключений. Кассовый обмен имеет более высокий приоритет; при перегрузке замедляется обработка Мониторинга. Для Аналитики и CSV следующего этапа применяются те же правила изоляции.

### Проверка
Реализация соответствует решению PM-DEC-195.
## REQ-DEC-165. Решение Product Manager

**Область:** technicalConstraints
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-180
**Применимость:** Следующий этап

На следующем этапе центральный сервис мониторинга маркировки поставляется и обновляется вместе с SetCentrum и работает без установленной серверной или магазинной части Set Mark. Сервис является отдельным компонентом функционального контура Set Mark; его жизненный цикл не должен зависеть от установки Set Mark у клиента.

### Проверка
Реализация соответствует решению PM-DEC-180.
## REQ-DEC-154. Решение Product Manager

**Область:** technicalConstraints
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-169, PM-DEC-180
**Применимость:** Следующий этап

Архитектура следующего этапа обеспечивает подключение ЭЦП, получение отклонений Честного знака и построение усечённых Обзора и Аналитики без установленной серверной и магазинной частей Set Mark. Эти операции выполняет отдельный центральный сервис мониторинга маркировки, поставляемый с SetCentrum и функционально принадлежащий контуру Set Mark.

### Проверка
Реализация соответствует решению PM-DEC-169.
## REQ-DEC-148. Решение Product Manager

**Область:** technicalConstraints
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-163
**Применимость:** MVP1

Поставка и запуск MVP не зависят от версии или обновления SetCentrum, поскольку интерфейс и необходимые контракты MVP входят в Set Mark и текущий Журнал нарушений. Совместимость версий для будущей инъекции интерфейса в SetCentrum определяется отдельно на следующем этапе.

### Проверка
Реализация соответствует решению PM-DEC-163.
## REQ-DEC-113. Решение Product Manager

## REQ-DEC-109. Прототипирование демонстрационного режима

**Область:** technicalConstraints
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-124
**Применимость:** Следующий этап

Прототипирование точки входа в подключение ЭЦП без установленного Set Mark и остальных состояний демонстрационного режима относится к следующему этапу и не входит в прототип MVP.

### Проверка
Прототип MVP не содержит сценария работы SetCentrum с визуализацией Set Mark при отсутствии установленного Set Mark.
## REQ-DEC-087. Решение Product Manager

**Область:** technicalConstraints
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-090, PM-DEC-128
**Применимость:** Следующий этап

На следующем этапе прототип должен показать действующую визуализацию Журнала нарушений непосредственно внутри целевой оболочки SetCentrum, но не обязан реализовывать техническую production-миграцию Журнала. Отдельными задачами этого этапа остаются перенос или совместимость URL, перенаправления, пользовательские закладки, сохранённые фильтры и пользовательское состояние, сохранение модели прав и интеграционные ссылки на старую визуализацию. Перенос интерфейса сам по себе не изменяет бизнес-логику Журнала.

### Проверка
Реализация соответствует решению PM-DEC-090.
## REQ-DEC-081. Решение Product Manager

**Область:** technicalConstraints
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-084
**Применимость:** Следующий этап

Прототип следующего этапа проверяет только наличие точки входа в подключение ЭЦП без лицензии, доступность этой точки пользователю с соответствующей административной привилегией и понятное объяснение следующего шага. Фактическое подключение и полный жизненный цикл сертификата в таком прототипе не реализуются. За пределами этого прототипа остаются дополнительные права на операции с ЭЦП, состояния подключения, проверка срока сертификата, замена и отзыв, ошибки авторизации, аудит, безопасное хранение ключей и сертификатов и восстановление после ошибок.

### Проверка
Реализация соответствует решению PM-DEC-084.
## REQ-DEC-013. Решение Product Manager

**Область:** technicalConstraints
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-013, PM-DEC-019, PM-DEC-128
**Применимость:** MVP1

Визуальный прототип MVP должен запускаться локально в браузере и показывать новую функциональность внутри текущего интерфейса Журнала нарушений. На этапе визуального прототипа реальные интеграции и backend не создаются; используются подготовленные демонстрационные данные без клиентских данных и секретов. Журнал нарушений сохраняет собственную действующую визуализацию, а новые экраны Мониторинга используют паттерны CSI UI. Моделирование оболочки и продуктовой навигации SetCentrum относится к следующему этапу. Отсутствие доступа к корпоративному npm-реестру не должно блокировать визуальный прототип. Production-стек, развёртывание и источник данных рабочего прототипа должны быть утверждены отдельно позднее.

### Проверка
Реализация соответствует решению PM-DEC-013.

## REQ-DEC-014. Решение Product Manager

**Область:** technicalConstraints
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-014, PM-DEC-019
**Применимость:** MVP1

Визуальный прототип должен запускаться в браузере на телефоне и представлять адаптивный веб-интерфейс функции Set Mark. Нативное приложение для iOS или Android не требуется.

### Проверка
Реализация соответствует решению PM-DEC-014.
## Что необходимо зафиксировать при закрытии вопроса

- обязательные или запрещённые технологии;
- обязательный способ поставки и запуска продукта;
- ограничения развёртывания;
- правила хранения и размещения данных;
- требования к обмену данными между частями системы;
- инфраструктурные ограничения, влияющие на эксперимент;
- ограничения пользовательского и торгового оборудования либо ссылку на раздел оборудования;
- внешние технические зависимости.

Не следует заранее проектировать production-архитектуру или выбирать стек. Подтверждённый стек и способ поставки обязательны только перед `WORKING_PROTOTYPE`. Инфраструктурный сайзинг не является входным требованием Product Compiler.

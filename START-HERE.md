# Начало работы с Product Compiler

## 1. Запуск

```text
python -m pip install -r requirements-tooling.txt
```

После этого напишите агенту:

```text
Начни работу над продуктом.
```

Укажите источники или выберите работу только из диалога.

## 2. Что будет создано

Требования читаются в таком порядке:

1. видение продукта;
2. границы текущей версии;
3. пользовательские сценарии;
4. общие продуктовые правила;
5. наблюдаемые требования к качеству;
6. открытые пункты для следующих этапов.

Один сценарий описывает одну законченную задачу пользователя. Product Manager не
обязан отвечать на вопросы об архитектуре, API, базах данных, развёртывании и
эксплуатационных механизмах.

## 3. Обязательный путь

```text
SOURCE_SETUP → INTAKE → PRODUCT_DEFINITION → HANDOFF_READY
```

После PRODUCT_DEFINITION можно добавить необязательную ветку:

- `NONE` — без прототипа;
- `VISUAL_ONLY` — визуальный прототип и его проверка;
- `VISUAL_AND_WORKING` — визуальный и рабочий прототипы с проверкой.

Выбор регистрируется:

```text
python tools/record_prototype_plan.py --plan VISUAL_ONLY --message "Точный ответ Product Manager"
```

Перед рабочим прототипом отдельно подтверждаются его технологический стек и
источник данных. Они не становятся production-архитектурой.

## 4. Вопросы

Немедленно задаётся только вопрос, который блокирует видение, границы или
основной сценарий. Остальные пункты сохраняются как неблокирующие; их можно
решить позже или передать системному аналитику и архитектору.

## 5. Фиксация и отчёты

После готовности продуктового определения:

```text
python tools/commit_requirements.py
python tools/finalize_phase_review.py --phase PRODUCT_DEFINITION --markdown reports/product-definition.md
```

Агент сам показывает отчёт и останавливается до отдельного подтверждения Product
Manager.

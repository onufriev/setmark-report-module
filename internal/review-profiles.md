# Профили проверки этапов

Один общий контрольный отчёт не заменяет проверки с разными целями. Для каждого этапа Product Compiler выбирает только применимые профили и фиксирует их в отчёте этапа.

## Доступные профили

- `PRODUCT_COMPLETENESS` — полнота продукта, ролей, правил, сценариев и критериев приёмки.
- `DOMAIN_CONSISTENCY` — единообразие терминов, сущностей, состояний и правил во всех документах.
- `UX_FLOW` — целостность пользовательских путей, переходов, ошибок и восстановления.
- `ARCHITECTURE_BOUNDARIES` — границы компонентов, зависимости, владение данными и ответственность.
- `INTEGRATION_RELIABILITY` — контракты, ошибки, повторы, идемпотентность и деградация интеграций.
- `SECURITY_AND_ACCESS` — аутентификация, авторизация, доступ к данным и аудит действий.
- `OPERABILITY` — установка, обновление, восстановление, наблюдаемость и эксплуатация.
- `HANDOFF_READINESS` — достаточность и проверяемость комплекта для передачи в разработку.

## Правила применения

1. Профили выбираются по содержанию проекта, а не по типу продукта.
2. Неприменимый профиль не выполняется и не создаёт обязательный файл.
3. Для `PRODUCT_DEFINITION` обязательны `PRODUCT_COMPLETENESS` и `DOMAIN_CONSISTENCY`.
4. Для `VISUAL_PROTOTYPE` и `VISUAL_VALIDATION` обязателен `UX_FLOW`.
5. Для `WORKING_PROTOTYPE` и `WORKING_VALIDATION` обязательны `ARCHITECTURE_BOUNDARIES` и `OPERABILITY`; остальные профили подключаются при наличии соответствующих требований.
6. Для `HANDOFF_READY` обязателен `HANDOFF_READINESS`.
7. Результат каждого профиля: `PASSED`, `PASSED_WITH_WARNINGS` или `BLOCKED`.
8. Открытый результат `BLOCKED` запрещает подтверждение отчёта этапа.

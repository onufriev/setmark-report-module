# Workflow Product Compiler

1. `SOURCE_SETUP` — выбрать режим источников и сохранить проверяемые snapshots.
2. `INTAKE` — извлечь факты, кандидаты UI и пробелы без объявления полноты.
3. `PRODUCT_DEFINITION` — закрыть каждую область до `VISUAL_PROTOTYPE`, зафиксировать baseline требований и получить отдельное утверждение отчёта.
4. `VISUAL_PROTOTYPE` — создать локальный кликабельный HTML/CSS/JS-прототип с `csi_ui-prototype-kit`, манифестом, данными и runbook.
5. Опционально после `VISUAL_PROTOTYPE` — при наличии исходников, указанных Product Manager, собрать `visual-prototype-storybook` с реальными компонентами и экранными stories. Отсутствие исходников не блокирует процесс.
6. `VISUAL_VALIDATION` — проверить сценарии с Product Manager/клиентом.
7. `WORKING_PROTOTYPE` — сначала подтвердить стек и источник данных, затем создать запускаемую реализацию и инструкцию.
8. `WORKING_VALIDATION` — проверить запуск, данные, health-check и ключевые сценарии.
9. `HANDOFF_READY` — собрать полный комплект для разработки.

Каждый переход: Markdown в `reports/` -> `finalize_phase_review.py` -> показ -> остановка -> отдельное подтверждение -> `approve_phase_review.py`.
## Итеративное продолжение

После изменения уже созданных артефактов процесс не начинается заново. Агент применяет `internal/restart-process.md`, находит первый затронутый этап, делает зависимые ревью устаревшими и создаёт новые ревизии только для реально изменённых этапов.


## Независимая проверка критиками

Критики не входят в обязательный workflow. Перед завершением значимого этапа агент один раз предлагает Product Manager дополнительную проверку и ждёт выбора. Без явного согласия критики не запускаются. Отказ не блокирует финализацию phase review и переход этапа. Если проверка выбрана, отчёт сохраняется в `critics/reports/` и может использоваться как дополнительный вход для официального отчёта.

# Системные сценарии

## REQ-DEC-040. Решение Product Manager

**Область:** systemScenarios
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-041
**Применимость:** MVP1

Любой переход из агрегированного представления в список инцидентов передаёт период и активные фильтры, использованные при расчёте источника перехода. Количество записей после перехода должно совпадать со значением показателя, объекта, категории или колонки графика.

Переход из блока «Объекты с наибольшим риском» использует ту же выборку критических инцидентов выбранного магазина и сбрасывает посторонние фильтры.

### Проверка
Реализация соответствует решению PM-DEC-041.
## REQ-DEC-021. Решение Product Manager

**Область:** systemScenarios
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-021; PM-DEC-054
**Применимость:** MVP1

Для MVP сквозной системный процесс функции внутри Set Mark должен выполняться следующим образом: Set Mark получает отклонение; функция сохраняет снимок исходных данных и создаёт один инцидент без дублирования; инцидент переходит из состояния «Получен» в состояние «Анализируется»; функция сопоставляет отклонение с доступными в Set Mark операциями, проверками и настройками; по зафиксированной версии правил формируются внутренний результат RA-01–RA-05, понятное пользователю наименование результата, объяснение, критичность, Контур устранения и рекомендация; потенциальная сумма штрафа не рассчитывается и не включается в результат анализа; инцидент переходит в состояние «Анализ завершён» либо «Ошибка обработки»; результат учитывается в обзоре, аналитике, CSV и ежедневных уведомлениях; при сбое исходное событие сохраняется, Set Mark восстанавливает получение данных, а функция автоматически повторяет обработку; ни один этап процесса не влияет на продажи и проверку кодов.

### Проверка
Реализация соответствует решениям PM-DEC-021 и PM-DEC-054.
## Сценарии, которые необходимо проверить на применимость

- запуск и обновление системы;
- восстановление после сбоя;
- резервное копирование и восстановление данных;
- синхронизация между узлами, магазинами, кассами и устройствами;
- поведение при ошибках оборудования или сети;
- ввод нового магазина, кассы или устройства в эксплуатацию;
- возврат кассы или устройства из ремонта;
- разделение касс или устройств на группы, если это влияет на продукт;
- offline-режим и последующее восстановление обмена данными.

Неприменимые сценарии должны быть явно отмечены как неприменимые решением Product Manager, а не молча пропущены.

# Бизнес-сценарии

## REQ-DEC-041. Решение Product Manager

**Область:** businessScenarios
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-042
**Применимость:** MVP1

Пользователь начинает с критических инцидентов, затем оценивает масштаб проблем по типам нарушений и просматривает необходимые действия, предотвращающие повторение таких нарушений в следующем периоде.

На Дашборде доступен топ-5 действий, на отдельной вкладке — полный список. Выполнение действий и контроль результата происходят вне системы.

Пользователь при необходимости формирует PDF-описание любого выбранного инцидента.

### Проверка
Реализация соответствует решению PM-DEC-042.
## REQ-DEC-030. Решение Product Manager

**Область:** businessScenarios
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-030
**Применимость:** MVP1

В основном пользовательском сценарии интерфейс сразу направляет внимание пользователя на критические инциденты, для которых установлен риск выставления автоштрафа. Такие инциденты визуально выделяются, выводятся приоритетно, а обзор позволяет сразу перейти к соответствующим объектам и инцидентам.

### Проверка
Реализация соответствует решению PM-DEC-030.
## REQ-DEC-023. Решение Product Manager

**Область:** businessScenarios
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-023
**Применимость:** MVP1

Для MVP функция внутри Set Mark должна поддерживать следующие бизнес-сценарии: аналитик по работе с маркировкой открывает обзор сети, находит магазины, кассы и виды нарушений с наибольшим риском или накоплением и определяет приоритет анализа; аналитик переходит к инциденту и изучает исходные данные, понятный результат проверки без технического кода `RA-*`, критичность, потенциальный штраф, Контур устранения и рекомендацию; аналитик использует фильтры и аналитику, чтобы выявить динамику и повторяющиеся нарушения; пользователь выгружает выбранные данные в CSV для дополнительного анализа и отчётности; настроенные получатели получают ежедневное уведомление о критичных нарушениях и переходят к соответствующим данным в Set Mark; администратор системы настраивает подключение, получателей уведомлений и срок хранения данных; при неполных или устаревших данных пользователь видит их состояние и ограничения, чтобы не принять ошибочное решение. Назначение ответственных, постановка задач и контроль устранения нарушений остаются вне MVP.

### Проверка
Реализация соответствует решению PM-DEC-023.
## Формат описания каждого сценария

- роль;
- исходная ситуация и предусловия;
- действие или последовательность действий;
- ожидаемый результат и бизнес-эффект;
- исключения и ошибки;
- зависимые сущности, настройки, оборудование и интеграции.

Нужно покрыть основные, редкие и критичные сценарии. При необходимости сценарии разделяются по ролям или процессам.

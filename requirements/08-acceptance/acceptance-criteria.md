# Критерии приёмки

## REQ-DEC-078. Решение Product Manager

**Область:** acceptanceCriteria
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-081
**Применимость:** MVP1

Приёмка должна покрывать `RU` и корректную страну не `RU`; действующую лицензию, лицензионное несоответствие по количеству и категории, 10-дневный льготный период, завершённый льготный период, подтверждённое отсутствие лицензии и неизвестный статус с историей и без неё; пользователей с базовым правом и без него, с рабочими и административными привилегиями. Проверяется, что полный режим открывает разрешённые функции, частичное лицензирование и несовпадение категории дают только предупреждение, ограниченный режим показывает только агрегаты ЧЗ и заглушки без утечки деталей, а для не `RU` Мониторинг, его API, процессы и ЭЦП отсутствуют. При недоступности Set Agent состояние пересчитывается по сохранённой дате окончания. Срок хранения не превышает 30 дней, удалённые данные не восстанавливаются. Отдельно выполняются сценарии точного массового поиска, множественного выбора магазинов и CSV из 23 колонок только по текущей выборке; эти операции недоступны в ограниченном режиме.

### Проверка
Реализация соответствует решению PM-DEC-081.
## REQ-AC-001. Поиск, фильтр магазинов и расширенный CSV

**Область:** acceptanceCriteria  
**Статус:** Подтверждено Product Manager  
**Основание:** PM-DEC-081  
**Применимость:** MVP1

Приёмка подтверждает:

1. Поиск по одному штрихкоду, одному артикулу и одному полному коду маркировки находит соответствующие инциденты.
2. Смешанные значения через запятую объединяются по логике «ИЛИ», пробелы игнорируются.
3. Можно выбрать несколько магазинов, выбрать все и сбросить выбор.
4. Фильтр магазинов совместно работает с периодом, поиском и остальными фильтрами.
5. CSV содержит 23 утверждённые колонки в заданном порядке.
6. CSV содержит только текущую выборку и корректно экранирует русские символы, запятые, точки с запятой и кавычки.

### Проверка

Сценарии выполняются на данных минимум двух магазинов, двух штрихкодов, двух артикулов и двух полных кодов маркировки.


## REQ-DEC-043. Решение Product Manager

**Область:** acceptanceCriteria
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-044
**Применимость:** MVP1

Приёмка дополнительно должна подтвердить:

1. Период и фильтры одинаково применяются на связанных экранах.
2. Число в кликабельном агрегате совпадает с числом открытых по нему инцидентов.
3. Каждый инцидент имеет один тип нарушения и не учитывается в разбивке дважды.
4. Действия, предотвращающие критические инциденты, расположены выше остальных.
5. Аналитика группирует период до 14 дней включительно по дням, более длительный период — по неделям.
6. Фильтры аналитики немедленно пересчитывают все показатели и график; два включённых фильтра применяются совместно.
7. Поиск находит инцидент по полному коду маркировки.
8. Блок состояния данных содержит только два согласованных сигнала.
9. Кнопка PDF формирует настоящий файл с согласованным составом и без исключённых сведений.
10. Диаграмма по типам нарушений учитывает выбранный период и активные фильтры Дашборда; сумма её значений совпадает с общим числом инцидентов текущей выборки.

### Проверка
Реализация соответствует решению PM-DEC-044.
## REQ-DEC-025. Решение Product Manager

**Область:** acceptanceCriteria
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-025, PM-DEC-081
**Применимость:** MVP1

Для MVP функция считается соответствующей требованиям, если:

1. Пользователь входит через действующую аутентификацию SetCentrum, открывает Set Mark в общей оболочке и видит только разрешённые объекты.
2. Обзор сети показывает период, два согласованных сигнала состояния данных, показатели и объекты с наибольшим риском.
3. Фильтры позволяют перейти от сети, магазина, кассы, товарной группы или вида нарушения к соответствующим инцидентам.
4. Для одного отклонения создаётся один инцидент с исходным снимком и системными состояниями обработки.
5. Карточка показывает понятный результат проверки без технического кода `RA-*`, объяснение, критичность, потенциальный штраф, Контур устранения и рекомендацию.
6. Устаревшие, неполные и неизвестные данные обрабатываются согласно утверждённым исключительным сценариям.
7. Аналитика, пороги, CSV и ежедневные уведомления используют согласованные данные и фильтры.
8. Основные экраны открываются не более чем за 3 секунды для 95% запросов, а инцидент появляется не позднее 24 часов.
9. Повторная доставка не создаёт дубликатов; после сбоя обработка автоматически продолжается без потери исходных событий.
10. Сбои функции не влияют на продажи и проверку кодов; управление задачами и ответственными отсутствует.

### Проверка
Реализация соответствует решению PM-DEC-025.

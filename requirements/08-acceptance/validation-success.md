# Критерий успешной проверки прототипа

## REQ-DEC-044. Решение Product Manager

**Область:** successSignal
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-045
**Применимость:** MVP1

Проверка прототипа считается успешной, если пользователь без дополнительных объяснений может:

1. Выбрать период.
2. Определить критические инциденты и объекты.
3. Понять распределение инцидентов по типам нарушений.
4. Увидеть приоритетные необходимые действия.
5. Перейти из любого кликабельного агрегата к совпадающей выборке инцидентов.
6. Применить фильтры аналитики и увидеть пересчёт показателей и графика.
7. Сформировать PDF по выбранному инциденту.

### Проверка
Реализация соответствует решению PM-DEC-045.
## REQ-DEC-026. Решение Product Manager

**Область:** successSignal
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-026
**Применимость:** MVP1

Идея считается подтверждённой, если представитель целевого пользователя на демонстрационных данных без дополнительных объяснений сможет:

1. На обзоре сети определить магазин, кассу или вид нарушения с наибольшим риском.
2. Перейти к соответствующим инцидентам и выбрать один для анализа.
3. По карточке инцидента понять, что произошло, почему получен результат проверки, насколько нарушение критично и к какому Контуру устранения относится, не интерпретируя технические коды `RA-*`.
4. Понять рекомендуемое следующее действие.
5. Увидеть ограничения при неполных или устаревших данных и не принять их за достоверный полный результат.
6. Вернуться к аналитике с сохранённым контекстом и выгрузить выбранные данные в CSV.
7. Подтвердить, что функция помогает определить приоритет проверки и дальнейших действий быстрее, чем анализ исходных данных вручную.

### Проверка
Реализация соответствует решению PM-DEC-026.

# Бизнес-правила

## REQ-DEC-007. Решение Product Manager

**Область:** businessRules
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-007
**Применимость:** MVP1

Для MVP утверждены следующие бизнес-правила:

- При получении одного отклонения True API создаётся один инцидент с обязательным результатом анализа `RA-01`–`RA-05`.
- Сопоставление выполняется по полному коду маркировки; расхождение времени показывается, но не блокирует сопоставление.
- Если код маркировки отсутствует, результат анализа — `RA-04 — Недостаточно данных`.
- Если тип отклонения неизвестен, результат анализа — `RA-05 — Требуется обновление правил анализа`.
- Если отклонение находится вне розничного выбытия, результат анализа — `RA-03 — Вне поддерживаемых процессов`.
- Подтверждённое нарушение получает результат `RA-01`.
- Найденный корректный сценарий, например возврат перед повторной продажей, получает результат `RA-02`.
- При проверке разрешительного режима сначала используется онлайн-проверка ЧЗ, затем ЛМ ЧЗ только при отсутствии ответа.
- Продажа, выполненная вопреки запрету или без разрешающего ответа, получает результат `RA-01`.
- Риск автоштрафа указывается только при наличии подтверждённой действующей нормы на дату кассовой операции.
- Накопительный порог меняет критичность агрегата магазина, но не отдельных инцидентов.
- Конфигурация Set Centrum считается возможным фактором, но не доказательством настроек на момент операции.
- Новая версия правил применяется только к новым инцидентам; ранее созданные инциденты автоматически не пересчитываются.

Каждый результат анализа должен объяснять использованные факты, цепочку операций, источник решения, применённое правило и ограничения данных.

### Проверка
Реализация соответствует решению PM-DEC-007.
## REQ-BR-001. Корреляция отклонений

**Область:** businessRules
**Статус:** Подтверждено источником
**Основание:** SRC-EV-007
**Применимость:** MVP1

Система должна сопоставлять отклонения Честного знака с записями журнала нарушений Set Mark по коду маркировки и временной метке.

### Проверка

Для каждого сопоставленного отклонения доступны использованные ключи корреляции и связанная запись журнала.

## REQ-BR-002. Последовательность онлайн- и офлайн-проверки

**Область:** businessRules
**Статус:** Подтверждено источником
**Основание:** SRC-EV-013, SRC-EV-015
**Применимость:** MVP1

При анализе кассовой проверки система должна учитывать онлайн- и офлайн-проверку кода маркировки как последовательные этапы разрешительного режима: офлайн-проверка применяется после отсутствия ответа онлайн-сервиса.

### Проверка

Объяснение инцидента различает результат онлайн-проверки, переход к офлайн-проверке и итоговое решение кассы.

## REQ-BR-003. Справочник отклонений

**Область:** businessRules
**Статус:** Подтверждено источником
**Основание:** SRC-EV-016
**Применимость:** MVP1

Категории, виды и результаты отклонений должны идентифицироваться по справочникам True API v704.0, страницы 1229–1234, до подключения более актуального официального справочника.

### Проверка

Код и название отклонения в каталоге соответствуют зарегистрированному снимку True API v704.0.

## REQ-DEC-001. Решение Product Manager

**Область:** businessRules
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-001
**Применимость:** MVP1

В область продукта входят все отклонения, возникшие при розничной реализации или выбытии, независимо от контура устранения; для каждого отклонения контур устранения указывается отдельно.

### Проверка
Реализация соответствует решению PM-DEC-001.

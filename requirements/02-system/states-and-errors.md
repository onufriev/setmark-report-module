# Ошибки, пустые и недоступные состояния

## REQ-DEC-171. Решение Product Manager

**Область:** statesErrors
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-186
**Применимость:** Следующий этап

Если за предыдущий календарный день новых критичных отклонений нет, ежедневный дайджест не формируется и это не считается ошибкой. При ошибке доставки система выполняет автоматические повторные попытки, сохраняет состояние доставки и показывает в настройках время и понятную причину последней ошибки. Успешная последующая доставка закрывает активное состояние ошибки, сохраняя историю.

### Проверка
Реализация соответствует решению PM-DEC-186.
## REQ-DEC-137. Решение Product Manager

**Область:** statesErrors
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-152
**Применимость:** MVP1

В MVP отсутствуют пользовательские и системные состояния выполнения автоматического анализа, включая RA-01–RA-05, «Анализируется», «Анализ завершён» и «Ошибка обработки анализа». Ошибки получения, сопоставления и полноты исходных данных продолжают отображаться без присвоения результата анализа.

## REQ-DEC-126. Решение Product Manager

**Область:** statesErrors
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-141
**Применимость:** MVP1

В MVP настройка подключения и ручной запуск True API доступны при действующей лицензии, лицензионном несоответствии и в течение 10-дневного льготного периода. Для этих операций состояния несоответствия и льготного периода не создают дополнительного предупреждения или ограничения. После окончания льготного периода, при подтверждённом состоянии «лицензии никогда не было» и при неизвестном статусе без достоверной истории настройка и запуск недоступны. При недоступности Set Agent доступ рассчитывается по последнему достоверному сохранённому состоянию и дате окончания. Получение данных без лицензионного доступа относится к следующему этапу.

### Проверка
Реализация соответствует решению PM-DEC-141.
## REQ-DEC-123. Решение Product Manager

**Область:** statesErrors
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-138
**Применимость:** MVP1

Для первой и последующих синхронизаций True API применяются состояния: «Данные ещё не загружены» до первого запуска; «Синхронизация выполняется» во время запроса без возможности параллельного повторного запуска; успешная загрузка с отклонениями; успешный пустой ответ «За выбранный период отклонения не найдены»; ошибка с причиной, временем и рекомендацией попробовать получить данные позднее без кнопки «Повторить»; устаревшие данные с датой последнего успешного получения; «Данные получены не по всем ИНН», если успешный результат отсутствует хотя бы для одного из подключённых ИНН. Другие варианты не называются частичной загрузкой.

### Проверка
Реализация соответствует решению PM-DEC-138.
## REQ-DEC-105. Состояния демонстрационного режима

**Область:** statesErrors
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-120
**Применимость:** Следующий этап

На следующем этапе в состояниях «лицензии никогда не было», «льготный период закончился» и «статус неизвестен без достоверной истории» применяется демонстрационный режим: усечённый Обзор, лицензионные заглушки закрытых разделов и доступная администратору точка начала подключения ЭЦП. Эти состояния не входят в MVP.

### Проверка
Каждое состояние следующего этапа показывает предусмотренное ограниченное представление и не раскрывает закрытые детали.
## REQ-DEC-083. Решение Product Manager

**Область:** statesErrors
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-086
**Применимость:** MVP1

Для клиента RU после проверки прав применяются следующие состояния. При действующей лицензии доступ полный. При лицензионном несоответствии доступ полный с неблокирующим предупреждением. В течение 10-дневного льготного периода доступ полный с предупреждением и остатком срока. При недоступности Set Agent и наличии достоверной даты окончания состояние пересчитывается по этой дате, включая льготный период, с предупреждением о невозможности актуализации. «Лицензии никогда не было» назначается только при явном подтверждении полной истории Set Agent. Предупреждения должны отличаться от ошибок доступа, объяснять конкретное состояние и не блокировать функции при полном доступе.

Усечённый Обзор, лицензионные заглушки и подключение ЭЦП при отсутствии полного лицензионного доступа относятся к следующему этапу по REQ-DEC-105 и не являются поведением MVP.

### Проверка
Реализация соответствует решению PM-DEC-086.
## REQ-DEC-038. Решение Product Manager

**Область:** statesErrors
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-039
**Применимость:** MVP1

В блоке «Состояние данных» показываются только два сигнала:

1. Результат последнего обращения в «Честный знак» за отчётом — успешно или с ошибкой — с датой и временем обращения.
2. Наличие или отсутствие связи с Set Centrum.

Без связи с Set Centrum анализ инцидентов невозможен. Проценты полноты, количество пропущенных записей и оценка качества данных в этом блоке не показываются.

### Проверка
Реализация соответствует решению PM-DEC-039.
## REQ-DEC-009. Решение Product Manager

**Область:** statesErrors
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-009, PM-DEC-138, PM-DEC-152
**Применимость:** MVP1

Для MVP утверждены следующие ошибки, пустые и недоступные состояния:

- Если нарушений за выбранный период нет, система показывает сообщение «Нарушения не обнаружены».
- Если данным не соответствует текущий набор фильтров, система сообщает об отсутствии результатов и предлагает действие «Сбросить фильтры».
- Во время загрузки система показывает индикатор загрузки и не выдаёт устаревший результат за актуальный.
- При задержке обновления данных система показывает предупреждение и время последнего успешного обновления.
- Если часть источников обогащения недоступна, система показывает доступные данные и явно отмечает недоступные, но не называет это частичной загрузкой True API.
- Если данных недостаточно для сопоставления, карточка перечисляет отсутствующие источники без присвоения результата анализа.
- Если вид отклонения неизвестен, карточка показывает исходное значение Честного знака без присвоения результата анализа.
- При ошибке получения или сопоставления система показывает понятное описание и идентификатор инцидента.
- При ошибке настройки интеграции пользователь Журнала нарушений видит проблемное подключение и причину ошибки.

### Проверка
Реализация соответствует решению PM-DEC-009.

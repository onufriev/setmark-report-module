# Функциональные требования

## REQ-DEC-169. Решение Product Manager

**Область:** functionalRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-184
**Применимость:** Следующий этап

На следующем этапе система один раз в сутки в 09:00 по часовому поясу SetCentrum формирует для организации email-дайджест о новых критичных отклонениях за предыдущий календарный день. Получатели задаются в настройках Set Mark. Ссылка из письма открывает Инциденты с соответствующими периодом и фильтрами. В усечённом режиме уведомления недоступны.

### Проверка
Реализация соответствует решению PM-DEC-184.
## REQ-DEC-161. Решение Product Manager

**Область:** functionalRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-176
**Применимость:** Следующий этап

На следующем этапе полный режим доступен при действующей лицензии, лицензионном несоответствии и в течение 10-дневного льготного периода. Усечённый режим включается, если лицензии никогда не было, льготный период закончился либо статус неизвестен без достоверной истории. Он предоставляет подключение ЭЦП, Обзор и Аналитику только по отклонениям Честного знака. Инциденты, карточки, Журнал нарушений, Необходимые действия, экспорты, уведомления и остальные настройки заблокированы. При временной недоступности Set Agent режим определяется по последнему достоверному состоянию и дате окончания лицензии.

### Проверка
Реализация соответствует решению PM-DEC-176.

## REQ-DEC-080. Решение Product Manager

**Область:** functionalRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-083, PM-DEC-176
**Применимость:** Следующий этап

В состояниях «лицензии никогда не было», «льготный период закончился» и «статус неизвестен без достоверной истории» пользователю доступны усечённые Обзор и Аналитика, построенные только по отклонениям ЛК ЧЗ/True API. Они содержат агрегаты и распределения, но не показывают строки или карточки инцидентов, кликабельные переходы к деталям, рекомендации, причины, чеки, настройки либо результаты сопоставления и содержат призыв приобрести Set Mark.

«Инциденты» и «Необходимые действия» остаются видимыми в навигации, но открывают лицензионные заглушки без реальных данных. Журнал нарушений, CSV, PDF, массовый поиск, ежедневные уведомления и изменение настроек недоступны, кроме разрешённого запуска подключения ЭЦП. При отсутствии подключения и данных для Обзора и Аналитики применяется отдельное пустое состояние по REQ-DEC-077.

### Проверка
Реализация соответствует решению PM-DEC-083.
## REQ-DEC-079. Решение Product Manager

**Область:** functionalRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-082, PM-DEC-126
**Применимость:** Следующий этап

На следующем этапе продукт отображается в SetCentrum как самостоятельный раздел по аналогии с Set Loyalty. На верхнем уровне Set Mark располагаются четыре равноправных раздела в порядке: «Обзор», «Мониторинг маркировки», «Настройки», «Журнал нарушений». Внутри «Мониторинга маркировки» располагаются «Инциденты», «Необходимые действия» и «Аналитика». «Обзор» и «Настройки» не должны быть вложены в Мониторинг, а «Журнал нарушений» должен быть последним пунктом меню Set Mark. Действующая визуализация Журнала отображается непосредственно в SetCentrum без автоматического изменения бизнес-логики Журнала. Функция «Кассы требуют внимания» остаётся в Настройках и группирует данные как «Магазин → Касса → выявленное расхождение или проблема настройки».

### Проверка
Реализация соответствует решению PM-DEC-082.
## REQ-DEC-077. Решение Product Manager

**Область:** functionalRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-080
**Применимость:** Следующий этап

Если для клиента RU ЭЦП не подключена и данные «Честного знака» ещё не получены, усечённый Обзор не должен показывать нулевые агрегаты как результат мониторинга. Вместо метрик система показывает отдельное пустое состояние «Нет подключения к Честному знаку» и объясняет, что данные недоступны. Пользователю с привилегией подключения ЭЦП доступно действие начала подключения; пользователю без этой привилегии показывается предложение обратиться к администратору. Пустое состояние не раскрывает детали инцидентов.

### Проверка
Реализация соответствует решению PM-DEC-080.

## REQ-FR-007. Работа без Set Mark в магазинах и при распределённой установке

**Область:** functionalRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-097, PM-DEC-117, PM-DEC-168, PM-DEC-176
**Применимость:** MVP1

Если Set Mark установлен в магазинах, в том числе при распределённой схеме, полная детализация формируется по доступным централизованному сервису данным Set Mark и SetRetail. Магазин, данные которого ещё не поступают в SetCentrum, учитывается только по данным «Честного знака»; интерфейс явно показывает неполноту источников и не имитирует наличие недоступной детализации.

### Проверка

Для магазина с доступными данными Set Mark и SetRetail открывается полная детализация; при отсутствии части данных пользователь видит признак неполноты источников.

**Статус:** Подтверждено Product Manager

## REQ-FR-004. Поиск по штрихкодам, артикулам и кодам маркировки

**Основание:** PM-DEC-051, PM-DEC-093

## REQ-FR-006. Расширенная выгрузка инцидентов в CSV

**Область:** functionalRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-093, PM-DEC-145
**Применимость:** Следующий этап

CSV формируется по текущей выборке и содержит 23 колонки:

1. ID инцидента.
2. Код правила.
3. Дата и время операции.
4. Магазин.
5. Город.
6. Касса.
7. Штрихкод.
8. Артикул.
9. Наименование товара.
10. Товарная группа.
11. Полный код маркировки.
12. Тип нарушения.
13. Описание исходного отклонения.
14. Результат проверки.
15. Критичность.
16. Риск автоштрафа.
17. Потенциальная сумма штрафа.
18. Установленная причина.
19. Рекомендуемое действие.
20. Контур устранения.
21. Статус анализа.
22. Номер чека или идентификатор операции.
23. Источник проверки.

Текстовые значения экранируются, файл формируется в UTF-8.

### Проверка

CSV содержит все 23 колонки в указанном порядке и только инциденты активной выборки.

## REQ-DEC-037. Решение Product Manager

**Область:** functionalRequirements

**Основание:** PM-DEC-038, PM-DEC-054, PM-DEC-055, PM-DEC-056, PM-DEC-145

Обзор и список инцидентов используют общий выбранный период.

Клик по показателю, объекту или типу отклонения открывает в списке «Инциденты» соответствующую выборку. Потенциальный штраф, результаты `RA-01`–`RA-05`, отдельная Аналитика, Необходимые действия и PDF относятся к следующему этапу.

## REQ-DEC-010. Решение Product Manager

**Область:** functionalRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-010, PM-DEC-145
**Применимость:** MVP1

Для MVP утверждён следующий состав функций:

- система получает отклонения True API и создаёт инциденты;
- система автоматически сопоставляет доступные данные источников без формирования результата анализа `RA-01`–`RA-05`;
- Обзор показывает основные агрегаты и распределение отклонений по сети, торговым точкам и кассам;
- пользователь может переходить от сети к торговой точке, кассе и инциденту;
- список инцидентов поддерживает фильтрацию и поиск по утверждённым аналитическим разрезам;
- карточка инцидента показывает данные Честного знака, Журнала нарушений, чека, проверок и настроек;
- пользователь может настраивать критичность видов отклонений;
- любой пользователь текущего Журнала нарушений может настраивать подключение к True API; ролевая модель и отдельная административная привилегия для этой операции в MVP отсутствуют;
- система показывает свежесть данных, состояние источников и ошибки интеграций.

Результаты анализа, рекомендации, CSV, PDF, отдельные разделы «Необходимые действия» и «Аналитика» и ежедневные уведомления относятся к следующему этапу.

Блокирование продаж, автоматическое исправление, назначение ответственных, управление задачами и контроль выполнения в функции MVP не входят.

### Проверка
Реализация соответствует решению PM-DEC-010.

## REQ-FR-003. Ежедневные уведомления

**Область:** functionalRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-145, PM-DEC-184

Система должна один раз в сутки отправлять настроенным получателям email-дайджест о новых критичных отклонениях за предыдущий календарный день. Отправка выполняется в 09:00 по часовому поясу SetCentrum через настроенный SMTP. Ссылка открывает соответствующую отфильтрованную выборку Инцидентов. ## REQ-DEC-033. Готовые и произвольный диапазоны дат

**Область:** functionalRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-034, PM-DEC-104, PM-DEC-145
**Применимость:** MVP1

В MVP Обзор и Инциденты используют единый явно выбранный период. Доступны готовые диапазоны «Сегодня», «7 дней», «30 дней» и вариант «Произвольный» в пределах фактического срока хранения. При первом открытии применяются последние 7 календарных дней, включая текущий день, в часовом поясе SetCentrum. Выбранный период сохраняется при переходе между Обзором, списком и карточкой. На следующем этапе тот же период применяется к Аналитике, необходимым действиям и выгрузкам.

### Проверка

В Обзоре, списке и карточке значения соответствуют одному выбранному периоду. По умолчанию выбраны последние 7 календарных дней с текущим днём. Произвольный диапазон не выходит за пределы сохранившихся данных, период виден пользователю и сохраняется между переходами.
## REQ-DEC-102. Условие видимости Set Mark в SetCentrum на следующем этапе

**Область:** functionalRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-117, PM-DEC-126
**Применимость:** Следующий этап

На следующем этапе точка входа и визуализация Set Mark в SetCentrum доступны только при установленном Set Mark актуальной совместимой версии либо в предусмотренном требованиями демонстрационном режиме. В MVP эта точка входа отсутствует. Отдельное включение администратором после выполнения условий этапа не требуется.

### Проверка
В MVP визуализация Set Mark в SetCentrum отсутствует; её условия появления проверяются на следующем этапе.

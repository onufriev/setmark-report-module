# Функциональные требования

## REQ-DEC-010. Решение Product Manager

**Область:** functionalRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-010
**Применимость:** MVP1

Для MVP утверждён следующий состав функций:

- система получает отклонения True API и создаёт инциденты;
- система автоматически сопоставляет доступные данные и формирует результат анализа `RA-01`–`RA-05`;
- обзор сети показывает показатели и накопление нарушений по сети, торговым точкам и кассам;
- пользователь может переходить от сети к торговой точке, кассе и инциденту;
- список инцидентов поддерживает фильтрацию и поиск по утверждённым аналитическим разрезам;
- карточка инцидента показывает исходные данные, связанные операции, результаты проверок, причину, риск, Контур устранения и рекомендацию;
- аналитика показывает динамику, накопление нарушений и достижение порогов;
- система ежедневно информирует настроенных получателей о критичных нарушениях;
- система формирует CSV по текущим данным и применённым фильтрам;
- Администратор системы может настраивать подключение к True API, получателей уведомлений и срок хранения данных;
- система показывает свежесть данных, состояние источников и ошибки интеграций.

Ручное пользовательское состояние «Новый / Просмотрен» и функция отметки инцидента как просмотренного в MVP не вводятся. У инцидента остаются только системные состояния обработки: `Получен → Анализируется → Анализ завершён / Ошибка обработки`.

Блокирование продаж, автоматическое исправление, назначение ответственных, управление задачами и контроль выполнения в функции MVP не входят.

### Проверка
Реализация соответствует решению PM-DEC-010.
## REQ-FR-001. Централизованный мониторинг

**Область:** functionalRequirements
**Статус:** Подтверждено источником
**Основание:** SRC-EV-003
**Применимость:** MVP1

Система должна агрегированно отображать нарушения по сети магазинов, торговым точкам, кассам, товарным категориям и типам ошибок.

### Проверка

Пользователь может перейти от обзора сети к данным по указанным измерениям.

## REQ-FR-002. Выгрузка данных

**Область:** functionalRequirements
**Статус:** Подтверждено источником
**Основание:** SRC-EV-004
**Применимость:** MVP1

Система должна позволять выгружать отображаемые сведения в CSV.

### Проверка

Пользователь получает CSV, соответствующий выбранным данным и фильтрам.

## REQ-FR-003. Ежедневные уведомления

**Область:** functionalRequirements
**Статус:** Подтверждено источником
**Основание:** SRC-EV-005
**Применимость:** MVP1

Система должна информировать ответственных лиц о критичных нарушениях в ежедневном режиме.

### Проверка

Для критичного нарушения формируется ежедневное уведомление для настроенных получателей.

## REQ-DEC-033. Произвольный диапазон дат

**Область:** functionalRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-033
**Применимость:** MVP1

На вкладках «Дашборд» и «Инциденты» пользователь должен иметь возможность указать произвольные даты начала и окончания периода.

### Проверка

На обеих вкладках доступны поля начала и окончания периода; после применения диапазона отображаемые данные соответствуют выбранным датам.

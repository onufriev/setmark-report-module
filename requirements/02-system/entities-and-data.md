# Бизнес-объекты, сущности и данные

## REQ-DEC-079. Решение Product Manager

**Область:** businessObjects
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-080
**Применимость:** MVP1

Инцидент хранит штрихкод, артикул, наименование товара, номер чека или идентификатор операции и источник проверки. Все эти поля относятся к той же операции, что полный код маркировки и временная метка инцидента, и используются согласованно в карточке, точном поиске и CSV.

### Проверка
Реализация соответствует решению PM-DEC-080.

**Статус:** Подтверждено Product Manager  
**Основание:** PM-DEC-080

## REQ-DEC-035. Решение Product Manager

**Область:** businessObjects
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-036
**Применимость:** MVP1

Каждый инцидент относится ровно к одному типу нарушения из каталога и учитывается в соответствующей разбивке один раз.

Критическим считается инцидент, для которого возможен автоштраф. Отдельный параллельный признак «Риск автоштрафа» не вводится. Денежное значение штрафа, если оно рассчитано, хранится и показывается как потенциальный, а не назначенный штраф.

Необходимое действие содержит формулировку действия, количество связанных инцидентов за выбранный период и признак предотвращения критических инцидентов. Статуса выполнения у действия нет.

### Проверка
Реализация соответствует решению PM-DEC-036.
## REQ-DEC-006. Модель сущностей и состояний

**Область:** businessObjects
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-006, PM-DEC-010
**Применимость:** MVP1

Для MVP утверждена следующая модель сущностей:

- Инцидент — центральная сущность; одно отклонение True API создаёт один инцидент.
- Отклонение True API хранится в инциденте как неизменяемый снимок исходных данных.
- Код маркировки хранится полностью и может участвовать в нескольких операциях и инцидентах.
- Кассовая операция включает операцию, вызвавшую отклонение, и доступную историю продаж, возвратов и отмен.
- Проверка марки включает результаты Set Mark, онлайн-проверки «Честного знака» и ЛМ ЧЗ.
- Конфигурация магазина содержит актуальные настройки Set Centrum на момент анализа и не считается историческим доказательством.
- Результат анализа включает `RA-01`–`RA-05`, один вид нарушения, критичность, потенциальный штраф, Контур устранения, объяснение и рекомендацию.
- Версия правил фиксирует, по какой версии каталога и правил выполнен анализ.

Системные состояния инцидента:

`Получен → Анализируется → Анализ завершён / Ошибка обработки`

Ручные пользовательские состояния, включая «Новый» и «Просмотрен», не вводятся.

Статусы «В работе» и «Исправлен», назначение ответственного и контроль выполнения не вводятся в MVP, поскольку управление задачами исключено из его границ.

### Проверка

Реализация соответствует решениям PM-DEC-006 и PM-DEC-010 и не вводит дополнительные сущности, ручные пользовательские состояния или состояния управления задачами.

## REQ-BO-001. Связь отклонения с внутренними данными

**Область:** businessObjects
**Статус:** Подтверждено источником
**Основание:** SRC-EV-007
**Применимость:** MVP1

Отклонение из Честного знака должно сопоставляться с записью журнала нарушений Set Mark по коду маркировки и временной метке; при отсутствии записи журнала используется последний успешный результат проверки в Честном знаке, если он доступен.

### Проверка

Для отклонения отображается связанная запись Set Mark либо явно указан использованный результат проверки Честного знака.

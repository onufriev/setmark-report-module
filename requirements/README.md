# Требования к продукту

`requirements/` — главный человекочитаемый источник истины.

## Объединение требований 28.08–31.08.2026

Требования из переданного набора 28.08–31.08.2026 разложены по соответствующим доменным файлам в каноническом формате `REQ-*`. Уточняющие решения Product Manager зарегистрированы в `product/evidence-register.json`. Исходная неизменённая копия сохранена в `reference-materials/product-requirements/requirements-since-2026-08-28.md` только для аудита и не является параллельным источником требований.

## Канонический формат

```md
## REQ-FR-001. Просмотр состояния сети

**Область:** functionalRequirements
**Статус:** Подтверждено источником
**Основание:** SRC-EV-001
**Применимость:** MVP1

Система должна показывать состояние сети по регионам.

### Проверка
Пользователь видит только доступные ему регионы.
```

Допускается чтение старого заголовка `FR-001` и блока с метаданными `ID требования`, но новые требования создаются только как `REQ-...`.

## Неизвестное требование

```md
## NEEDS_INPUT: Объекты продаж и их иерархия

**ID вопроса:** Q-001
**Область:** salesObjects
**Статус:** Требуется решение

**Вопрос:** Какие уровни объектов используются?
**Что известно:** Полная иерархия не подтверждена.
**Почему важно:** Иерархия определяет навигацию и права.
**Рекомендация Product Compiler:** Предложение, которое нельзя применять без ответа.
```

## Полнота

Каждая область из `internal/domain-catalog.json` обязана иметь:

- подтверждённое требование;
- подтверждённую неприменимость;
- или `NEEDS_INPUT`.

Пустая область или отсутствующий файл являются ошибкой индекса. Все области, обязательные до `VISUAL_PROTOTYPE`, блокируют создание визуального прототипа, даже если профиль продукта не распознан.

## Фиксация требований

После прохождения gate:

```bash
python tools/commit_requirements.py
```

Команда создаёт неизменяемую базовую линию в `product/requirements-baseline.json`. После любого смыслового изменения требований baseline нужно сформировать заново.

# Данные, телеметрия, свежесть и полнота

## REQ-DEC-076. Решение Product Manager

**Область:** dataRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-077
**Применимость:** MVP1

Set Agent должен возвращать дату окончания лицензии Set Mark и признак, позволяющий подтвердить полноту истории для состояния «лицензии никогда не было». SetCentrum хранит последнее достоверное состояние лицензии, дату и время его последнего успешного получения и дату окончания, полученную от Set Agent. Значения сохраняются вместе как один версионированный снимок и используются для автономного расчёта состояния. Отсутствие снимка означает «статус неизвестен, достоверной истории нет», а не подтверждённое отсутствие лицензии.

### Проверка
Реализация соответствует решению PM-DEC-077.
## REQ-DEC-058. Решение Product Manager

**Область:** dataRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-059
**Применимость:** MVP1

Календарный срок хранения данных Мониторинга рассчитывается по дате события в часовом поясе SetCentrum. День события считается первым календарным днём хранения; при сроке 30 дней запись доступна в день события и следующие 29 календарных дней, после чего физически удаляется в начале 31-го календарного дня. Для настроенного меньшего срока применяется та же схема включительного подсчёта.

### Проверка
Реализация соответствует решению PM-DEC-059.
## REQ-DEC-057. Решение Product Manager

**Область:** dataRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-058
**Применимость:** MVP1

Срок хранения данных Мониторинга составляет 30 календарных дней, если отдельная настройка срока хранения Set Mark отсутствует. Если настройка задана меньше 30 дней, применяется настроенное значение; если она превышает 30 дней, фактический срок ограничивается 30 календарными днями. По окончании фактического срока данные физически удаляются. Удалённые данные не восстанавливаются после покупки или возобновления лицензии; после восстановления доступа пользователь видит только фактически сохранившуюся историю.

### Проверка
Реализация соответствует решению PM-DEC-058.
## REQ-DEC-056. Решение Product Manager

**Область:** dataRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-057
**Применимость:** MVP1

Для клиента со страной RU после настройки Set Mark и подключения ЭЦП система продолжает получать, обрабатывать и хранить данные Мониторинга независимо от состояния лицензии, в том числе если лицензии никогда не было или льготный период закончился. Лицензионные ограничения управляют пользовательским доступом к функциям и деталям, но сами по себе не останавливают поступление данных. Хранение выполняется в пределах установленного срока хранения.

### Проверка
Реализация соответствует решению PM-DEC-057.
## REQ-DEC-052. Решение Product Manager

**Область:** dataRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-053
**Применимость:** MVP1

Система может назначить состояние «лицензии никогда не было» только при явном достоверном подтверждении Set Agent, что у клиента никогда не существовало активной лицензии Set Mark. Отсутствие локальной истории или ответа Set Agent не является таким подтверждением и приводит к состоянию «статус неизвестен, достоверной истории нет».

### Проверка
Реализация соответствует решению PM-DEC-053.
## REQ-DEC-051. Решение Product Manager

**Область:** dataRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-052
**Применимость:** MVP1

SetCentrum должен хранить достоверные исторические данные о последней активной лицензии Set Mark. Без таких исторических данных система не может отличить отсутствие лицензии в прошлом от невозможности определить её состояние и не должна назначать состояние «лицензии никогда не было»; применяется состояние «статус неизвестен, достоверной истории нет».

### Проверка
Реализация соответствует решению PM-DEC-052.
## REQ-DEC-039. Решение Product Manager

**Область:** dataRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-040
**Применимость:** MVP1

Для инцидента хранится и отображается полный код маркировки; поиск должен находить инцидент по точному полному коду.

Для состояния данных хранятся результат, дата и время последнего обращения за отчётом в «Честный знак», а также состояние связи с Set Centrum.

PDF формируется по данным выбранного инцидента: фиксирует факты, последовательность событий, результат проверки и его обоснование; для допустимого сценария объясняет отсутствие нарушения со стороны ритейлера. В PDF указывается только название организации. Рекомендации, потенциальный штраф, подпись и специальное назначение документа в заголовке не включаются.

### Проверка
Реализация соответствует решению PM-DEC-040.
## REQ-DEC-018. Решение Product Manager

**Область:** dataRequirements
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-018, PM-DEC-019
**Применимость:** MVP1

Для одной торговой сети функция Set Mark должна поддерживать до 25 000 магазинов и до 40 000 касс. Максимальный объём обработки составляет до 100 000 отклонений в сутки; значение рассчитано исходя из 2,5 отклонения на одну кассу при максимальном количестве касс. Инцидент должен появляться в функции не позднее чем через 24 часа после получения соответствующего события Set Mark или «Честным знаком».

### Проверка
Реализация соответствует решению PM-DEC-018.
## REQ-DATA-001. Данные отклонения Честного знака

**Область:** dataRequirements
**Статус:** Подтверждено источником
**Основание:** SRC-EV-006, SRC-EV-016
**Применимость:** MVP1

Система должна получать сведения об отклонениях Честного знака и сохранять коды категорий, видов и результатов в соответствии со справочниками True API.

### Проверка

Для импортированного отклонения сохранены исходные коды и доступно их человекочитаемое название.

## REQ-DATA-002. Данные для корреляции

**Область:** dataRequirements
**Статус:** Подтверждено источником
**Основание:** SRC-EV-007, SRC-EV-012
**Применимость:** MVP1

Для сопоставления отклонения должны быть доступны код маркировки, временная метка и данные журнала нарушений Set Mark; при отсутствии записи журнала должен быть доступен последний успешный результат проверки Честного знака, если источник его предоставляет.

### Проверка

Система сохраняет использованные данные корреляции и явно показывает отсутствие недоступных данных.

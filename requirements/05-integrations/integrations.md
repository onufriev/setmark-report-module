# Интеграции

## REQ-DEC-063. Решение Product Manager

**Область:** integrations
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-064
**Применимость:** MVP1

Интеграция с True API «Честного знака», обработка ответов и хранение полученных данных реализуются и эксплуатируются в backend Set Mark. SetCentrum предоставляет оболочку, навигацию и пользовательский интерфейс к функциям Set Mark. Размещение интерфейса в SetCentrum не переносит интеграционную логику или владение данными в backend SetCentrum; взаимодействие интерфейса с данными выполняется через контракты Set Mark.

### Проверка
Реализация соответствует решению PM-DEC-064.
## REQ-DEC-032. Решение Product Manager

**Область:** integrations
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-032
**Применимость:** MVP1

Сейчас напрямую с Честным знаком взаимодействует только кассовое ПО. Интеграции Set Mark с Честным знаком не существует. Для нового модуля необходимо отдельно разработать новую интеграцию Set Mark с предоставленным API Честного знака для получения отклонений. Полученные через эту новую интеграцию отклонения сохраняются в Set Mark и используются функцией для создания и анализа инцидентов.

### Проверка
Архитектура и реализация не предполагают наличия действующей интеграции Set Mark с Честным знаком: отдельно показаны существующее прямое взаимодействие кассового ПО с Честным знаком и новая интеграция Set Mark с API Честного знака для получения отклонений.
## REQ-DEC-019. Решение Product Manager

**Область:** integrations
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-019, PM-DEC-064
**Применимость:** MVP1

Проектируемая возможность должна быть реализована как функция существующего продукта Set Mark, а не как самостоятельный продукт или автономный программный модуль. Пользовательский интерфейс Set Mark размещается в оболочке SetCentrum и использует её продуктовую навигацию, при этом интеграционная логика и владение данными остаются в backend Set Mark. Отдельная установка, обновление, запуск и лицензирование функции не требуются; у неё нет собственной аутентификации, инфраструктуры, SLA и аппаратной части. Прямые интеграции пользовательской функции с кассами, Set Retail или True API не требуются: данные предоставляет backend Set Mark через свои контракты. Доступ с телефона реализуется через адаптивный веб-интерфейс. Визуальный прототип должен показывать Set Mark внутри SetCentrum, а не отдельное приложение.

### Проверка
Реализация соответствует решению PM-DEC-019.
## Что необходимо зафиксировать для каждой интеграции

- назначение и бизнес-ценность;
- направление обмена данными;
- передаваемые данные;
- формат, протокол и способ обмена, если заданы;
- требования к доступности и свежести;
- аутентификацию и авторизацию;
- ошибки, тайм-ауты и правила повторных попыток;
- что является реальной интеграцией в прототипе, а что допустимо имитировать.

Для значимых интеграций допустимо создавать отдельные файлы, сохраняя ссылки и трассировку.

## REQ-INT-001. Получение отклонений True API

**Область:** integrations
**Статус:** Подтверждено источником
**Основание:** SRC-EV-006
**Применимость:** MVP1

В составе нового модуля должна быть разработана новая интеграция Set Mark с API Честного знака. Через неё Set Mark должен периодически получать зарегистрированные для ИНН клиента отклонения методом True API 8.3.15.1 «Выгрузка сведений об отклонениях» и сохранять результат для использования функцией.

### Проверка

Новая интеграция Set Mark с True API получает данные для заданного ИНН и сохраняет результат обработки каждого запроса; проверка не опирается на несуществующую действующую интеграцию Set Mark с Честным знаком.

## REQ-INT-002. Получение событий Set Mark

**Область:** integrations
**Статус:** Подтверждено источником
**Основание:** SRC-EV-012
**Применимость:** MVP1

Новая функция должна использовать сообщения о возможных нарушениях, уже загруженные в журнал нарушений Set Mark Centrum и доступные Set Mark.

### Проверка

Полученное Set Mark сообщение доступно функции для сопоставления с отклонением Честного знака без отдельной прямой интеграции функции с Set Mark Centrum.

## REQ-INT-003. Контекст разрешительного режима

**Область:** integrations
**Статус:** Подтверждено источником
**Основание:** SRC-EV-013, SRC-EV-014, SRC-EV-015
**Применимость:** MVP1

Кассовое ПО напрямую взаимодействует с онлайн Честным знаком и ЛМ ЧЗ. Данные о выполненных кассовым ПО проверках, переданные в Set Mark существующими механизмами обмена с кассой, должны позволять функции различить онлайн-проверку, последующую офлайн-проверку и продажу при отсутствии ответа обоих сервисов.

### Проверка

Для операции доступны канал проверки, результат каждого выполненного этапа и итоговое решение кассы.

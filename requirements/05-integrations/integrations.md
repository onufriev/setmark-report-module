# Интеграции

## REQ-DEC-029. Решение Product Manager

**Область:** integrations
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-029
**Применимость:** MVP1

Текущая интеграция Set Mark с Честным знаком не предоставляет отклонения. Для модуля необходимо отдельно разработать получение отклонений через предоставленный API Честного знака. Полученные отклонения сохраняются в Set Mark и используются функцией для создания и анализа инцидентов.

### Проверка
Реализация соответствует решению PM-DEC-029.
## REQ-DEC-019. Решение Product Manager

**Область:** integrations
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-019
**Применимость:** MVP1

Проектируемая возможность должна быть реализована как новая функция внутри существующего продукта Set Mark, а не как самостоятельный продукт или автономный программный модуль. Функция должна работать внутри интерфейса Set Mark и использовать его навигацию, компоненты и ролевую модель. Отдельная установка, обновление, запуск и лицензирование функции не требуются; у неё нет собственной аутентификации, инфраструктуры, SLA и аппаратной части. Интеграции выполняет существующий Set Mark, а функция использует уже полученные и сохранённые им данные; прямые интеграции функции с кассами, Set Retail, Set Centrum или True API не требуются, если данные уже поступают в Set Mark. Доступ с телефона реализуется через адаптивный веб-интерфейс Set Mark. Визуальный прототип должен показывать новый раздел и сценарий Set Mark, а не отдельное приложение.

### Проверка
Реализация соответствует решению PM-DEC-019.
## Что необходимо зафиксировать для каждой интеграции

- назначение и бизнес-ценность;
- направление обмена данными;
- передаваемые данные;
- формат, протокол и способ обмена, если заданы;
- требования к доступности и свежести;
- аутентификацию и авторизацию;
- ошибки, тайм-ауты и правила повторных попыток;
- что является реальной интеграцией в прототипе, а что допустимо имитировать.

Для значимых интеграций допустимо создавать отдельные файлы, сохраняя ссылки и трассировку.

## REQ-INT-001. Получение отклонений True API

**Область:** integrations
**Статус:** Подтверждено источником
**Основание:** SRC-EV-006
**Применимость:** MVP1

Set Mark должен периодически получать зарегистрированные для ИНН клиента отклонения через метод True API 8.3.15.1 «Выгрузка сведений об отклонениях» и сохранять результат для использования функцией.

### Проверка

Механизм получения отклонений через True API получает данные для заданного ИНН и сохраняет результат обработки каждого запроса.

## REQ-INT-002. Получение событий Set Mark

**Область:** integrations
**Статус:** Подтверждено источником
**Основание:** SRC-EV-012
**Применимость:** MVP1

Новая функция должна использовать сообщения о возможных нарушениях, уже загруженные в журнал нарушений Set Mark Centrum и доступные Set Mark.

### Проверка

Полученное Set Mark сообщение доступно функции для сопоставления с отклонением Честного знака без отдельной прямой интеграции функции с Set Mark Centrum.

## REQ-INT-003. Контекст разрешительного режима

**Область:** integrations
**Статус:** Подтверждено источником
**Основание:** SRC-EV-013, SRC-EV-014, SRC-EV-015
**Применимость:** MVP1

Существующие механизмы Set Mark должны предоставлять функции данные, позволяющие различить онлайн-проверку, последующую офлайн-проверку и продажу при отсутствии ответа обоих сервисов.

### Проверка

Для операции доступны канал проверки, результат каждого выполненного этапа и итоговое решение кассы.

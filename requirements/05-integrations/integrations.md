# Интеграции

## NEEDS_INPUT: Интеграции

**ID вопроса:** Q-016
**Область:** integrations
**Статус:** Требуется решение

**Вопрос:** С какими системами продукт должен взаимодействовать в прототипе или первой версии?
**Что известно:** Пока не установлено из подтверждённых источников.
**Почему важно:** Нужно отделить реальные интеграции от имитаций.
**Рекомендация Product Compiler:** Сформировать предложение только после анализа источников; не применять без подтверждения Product Manager.

## Что необходимо зафиксировать для каждой интеграции

- назначение и бизнес-ценность;
- направление обмена данными;
- передаваемые данные;
- формат, протокол и способ обмена, если заданы;
- требования к доступности и свежести;
- аутентификацию и авторизацию;
- ошибки, тайм-ауты и правила повторных попыток;
- что является реальной интеграцией в прототипе, а что допустимо имитировать.

Для значимых интеграций допустимо создавать отдельные файлы, сохраняя ссылки и трассировку.

## REQ-INT-001. Получение отклонений True API

**Область:** integrations
**Статус:** Подтверждено источником
**Основание:** SRC-EV-006
**Применимость:** MVP1

Система должна периодически получать зарегистрированные для ИНН клиента отклонения через метод True API 8.3.15.1 «Выгрузка сведений об отклонениях».

### Проверка

Интеграция получает отклонения для заданного ИНН и сохраняет результат обработки каждого запроса.

## REQ-INT-002. Получение событий Set Mark

**Область:** integrations
**Статус:** Подтверждено источником
**Основание:** SRC-EV-012
**Применимость:** MVP1

Система должна получать сообщения о возможных нарушениях, загруженные в журнал нарушений Set Mark Centrum.

### Проверка

Полученное сообщение Set Mark доступно для сопоставления с отклонением Честного знака.

## REQ-INT-003. Контекст разрешительного режима

**Область:** integrations
**Статус:** Подтверждено источником
**Основание:** SRC-EV-013, SRC-EV-014, SRC-EV-015
**Применимость:** MVP1

Интеграция должна предоставлять данные, позволяющие различить онлайн-проверку, последующую офлайн-проверку и продажу при отсутствии ответа обоих сервисов.

### Проверка

Для операции доступны канал проверки, результат каждого выполненного этапа и итоговое решение кассы.

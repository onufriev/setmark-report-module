## REQ-DEC-192. Приёмка только через реальное подключение True API

**Область:** integrations
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-207
**Применимость:** MVP1

Полная приёмка MVP без рабочей ЭЦП и реального подключения к ЛК Честного знака невозможна. Отдельный демонстрационный, эмуляционный или тестовый режим True API в MVP не создаётся. Без подключения проверяются только части, не зависящие от получения данных. Получение отклонений, состояния синхронизации, создание инцидентов, сопоставление, Обзор и карточка принимаются только на фактических данных реального подключения. При временной недоступности True API, ЭЦП или тестовой организации зависимая часть приёмки переносится до восстановления доступа; это не считается дефектом продукта, но выпуск нельзя признать полностью принятым. Проверочные запуски учитывают реальные квоты True API. Ошибки подключения проверяются управляемым нарушением доступности в защищённом испытательном контуре без подмены ответов синтетическими данными.

### Проверка
Реализация соответствует решению PM-DEC-207.

## REQ-DEC-127. Решение Product Manager

**Область:** integrations
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-142
**Применимость:** MVP1

В MVP настройка подключения и ручной запуск True API доступны при действующей лицензии, лицензионном несоответствии и в течение 10-дневного льготного периода. Для этих операций состояния несоответствия и льготного периода не создают дополнительного предупреждения или ограничения. После окончания льготного периода, при подтверждённом состоянии «лицензии никогда не было» и при неизвестном статусе без достоверной истории настройка и запуск недоступны. При недоступности Set Agent доступ рассчитывается по последнему достоверному сохранённому состоянию и дате окончания. Получение данных без лицензионного доступа относится к следующему этапу.

### Проверка
Реализация соответствует решению PM-DEC-142.

## REQ-DEC-075. Решение Product Manager

**Область:** integrations
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-078, PM-DEC-130, PM-DEC-170
**Применимость:** MVP1

Полный режим соответствует решению PM-DEC-078; демонстрационный режим без backend Set Mark соответствует PM-DEC-170 и не реализуется до определения владельца интеграции.
## REQ-DEC-032. Решение Product Manager

**Область:** integrations
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-032
**Применимость:** MVP1

Сейчас напрямую с Честным знаком взаимодействует только кассовое ПО. Интеграции Set Mark с Честным знаком не существует. Для нового модуля необходимо отдельно разработать новую интеграцию Set Mark с предоставленным API Честного знака для получения отклонений. Полученные через эту новую интеграцию отклонения сохраняются в Set Mark и используются функцией для создания и анализа инцидентов.

### Проверка
Архитектура и реализация не предполагают наличия действующей интеграции Set Mark с Честным знаком: отдельно показаны существующее прямое взаимодействие кассового ПО с Честным знаком и новая интеграция Set Mark с API Честного знака для получения отклонений.
## REQ-DEC-019. Решение Product Manager

**Область:** integrations
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-019, PM-DEC-078, PM-DEC-130
**Применимость:** MVP1

Проектируемая возможность должна быть реализована как функция существующего продукта Set Mark, а не как самостоятельный продукт или автономный программный модуль. В MVP пользовательский интерфейс размещается в текущем Журнале нарушений Set Mark, а интеграционная логика и владение данными остаются в backend Set Mark. Отдельная установка, запуск и лицензирование функции не требуются; она поставляется с актуальной версией Set Mark и не имеет собственной аутентификации, инфраструктуры, SLA и аппаратной части. Прямые интеграции пользовательской функции с кассами, Set Retail или True API не требуются: данные предоставляет backend Set Mark через свои контракты. Доступ с телефона реализуется через адаптивный веб-интерфейс. Инъекция пользовательского интерфейса в SetCentrum относится к следующему этапу.

### Проверка
Реализация соответствует решению PM-DEC-019.
## Что необходимо зафиксировать для каждой интеграции

- назначение и бизнес-ценность;
- направление обмена данными;
- передаваемые данные;
- формат, протокол и способ обмена, если заданы;
- требования к доступности и свежести;
- аутентификацию и авторизацию;
- ошибки, тайм-ауты и правила повторных попыток;
- что является реальной интеграцией в прототипе, а что допустимо имитировать.

Для значимых интеграций допустимо создавать отдельные файлы, сохраняя ссылки и трассировку.

## REQ-INT-001. Получение отклонений True API

**Область:** integrations
**Статус:** Подтверждено Product Manager
**Основание:** PM-DEC-111
**Применимость:** MVP1

В составе нового модуля должна быть разработана новая интеграция Set Mark с API Честного знака. Через неё Set Mark должен получать зарегистрированные для ИНН клиента отклонения методом True API 8.3.15.1 «Выгрузка сведений об отклонениях» и сохранять результат для использования функцией.

В MVP1 синхронизацию вручную запускает сотрудник с рабочей УКЭП. Автоматическая периодика остаётся целевым будущим режимом и включается после появления допустимой подписи или авторизации, доступной Set Mark 24/7.

### Проверка

Новая интеграция Set Mark с True API по ручному запуску получает данные для разрешённого ИНН и сохраняет результат обработки каждого запроса; повторная авторизация продолжает существующий SyncRun. Архитектура допускает включение автоматической периодики без изменения ingestion-контракта.

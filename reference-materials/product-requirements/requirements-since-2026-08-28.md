# Новые требования, сформированные с 28.08.2026

## 1. Назначение документа

Документ содержит самостоятельный набор требований, сформированных и уточнённых начиная с 28.08.2026. Он предназначен для переноса решений в другой проект без необходимости читать историю обсуждений Set Mark.

Набор охватывает:

- включение Set Mark в оболочку SetCentrum;
- демонстрационный и ограниченный режимы при отсутствии лицензии;
- матрицу доступности по стране, лицензии и правам;
- правила определения состояния лицензии и льготного периода;
- хранение данных при ограниченном доступе;
- визуальные источники и состав навигации;
- границы демо-версии;
- повторно подтверждённые требования к поиску и экспорту, необходимые для целостности решения.

Требования ниже имеют приоритет над более ранними решениями, если возникает прямое противоречие в вопросах лицензирования, страны, структуры навигации или источников визуального оформления.

## 2. Термины

| Термин | Определение |
|---|---|
| Set Mark | Лицензируемый продукт, в состав которого входят Журнал нарушений и Мониторинг маркировки. |
| SetCentrum | Общая пользовательская оболочка и точка входа в продукты. |
| Журнал нарушений, ЖН | Существующая функция Set Mark с записями о событиях кассовых проверок. |
| Мониторинг маркировки | Новая функция анализа отклонений Честного знака с Инцидентами, Необходимыми действиями и Аналитикой. |
| Отклонение ЧЗ | Зафиксированное Честным знаком отклонение. Наличие марки в данных ЛК ЧЗ/True API означает, что отклонение уже допущено. |
| Инцидент | Объект Мониторинга, созданный на основании одного отклонения ЧЗ и обогащённый данными ЖН, чека, проверок и настроек. |
| Усечённый Обзор | Доступный без лицензии обзор, содержащий только агрегаты отклонений ЧЗ без списка и карточек инцидентов. |
| Лицензионное несоответствие | Есть хотя бы одна действующая лицензия Set Mark, но лицензий недостаточно для всех магазинов либо лицензия относится к другой товарной категории. |
| Достоверная история лицензии | Последнее успешно полученное и сохранённое состояние лицензии. |
| ЭЦП | Электронная подпись, используемая для подключения к ЛК Честного знака. |

## 3. Принципы лицензирования

### NEW-LIC-001. Одна лицензия на продукт

Журнал нарушений и Мониторинг маркировки используют одну лицензию Set Mark. Отдельная лицензия для Мониторинга, Журнала или демонстрационного режима не вводится.

### NEW-LIC-002. Отсутствие отдельной пробной лицензии

Отдельного типа «пробная лицензия» нет. Обычная лицензия с ограниченным сроком действия считается действующей до указанной даты окончания и после истечения обрабатывается по общим правилам.

### NEW-LIC-003. Лицензионное несоответствие

Частичное лицензирование и лицензия другой товарной категории рассматриваются как лицензионное несоответствие при условии, что существует хотя бы одна действующая лицензия Set Mark.

В этом состоянии:

- функциональность Set Mark в SetCentrum не ограничивается;
- пользователь видит понятное предупреждение с причиной несоответствия;
- пользователю предлагается докупить необходимое количество или нужную категорию лицензий;
- предупреждение не должно блокировать работу и не должно скрывать данные.

Ноль действующих лицензий не является лицензионным несоответствием. Для него применяется состояние «лицензии никогда не было» либо «льготный период закончился».

### NEW-LIC-004. Источник состояния лицензии

Set Agent должен возвращать дату окончания лицензии. Сервер SetCentrum должен хранить:

- последнее достоверное состояние лицензии;
- дату и время последнего успешного получения лицензии;
- дату окончания лицензии, полученную от Set Agent.

Если дата и время последнего получения лицензии отсутствуют, считается, что лицензии никогда не было.

### NEW-LIC-005. Льготный период

После окончания лицензии действует льготный период продолжительностью не более 10 календарных дней.

Правила расчёта:

1. Используются календарные, а не рабочие дни.
2. Расчёт производится в часовом поясе SetCentrum.
3. Ограничения включаются сразу после завершения десятого дня.
4. Новое состояние применяется только при создании новой пользовательской сессии.
5. Уже открытая сессия не меняет доступ до повторного входа или создания новой сессии.
6. Истечение лицензии имеет приоритет над признаком лицензионного несоответствия.

### NEW-LIC-006. Недоступность проверки лицензии

Если Set Agent недоступен или состояние лицензии определить невозможно:

- при наличии достоверной истории используется последнее достоверное состояние и показывается предупреждение о невозможности актуализировать лицензию;
- при отсутствии достоверной истории применяется то же ограниченное поведение, что и для состояния «Лицензии никогда не было», с отдельным предупреждением о недоступности проверки.

Недоступность Set Agent не должна автоматически открывать полный доступ или автоматически включать отдельный демо-режим.

### NEW-LIC-007. Состав усечённого Обзора

Без лицензии усечённый Обзор должен содержать только:

- общее количество отклонений Честного знака за доступный период;
- количество магазинов с отклонениями;
- количество видов отклонений;
- распределение отклонений по видам.

Усечённый Обзор:

- строится только по отклонениям ЛК ЧЗ/True API;
- не объединяет агрегаты Журнала нарушений;
- не показывает отдельные строки и карточки инцидентов;
- не даёт перейти к деталям через кликабельные агрегаты;
- не содержит рекомендаций, причин, чеков, настроек или результатов сопоставления;
- содержит призыв приобрести лицензию Set Mark.

### NEW-LIC-008. Заглушки закрытых разделов

При отсутствии полного доступа разделы Инциденты, Необходимые действия и Аналитика должны оставаться видимыми как точки навигации, но открывать заглушку. Заглушка должна:

- сообщать, что требуется лицензия Set Mark;
- кратко объяснять пользу закрытой функции;
- предлагать приобрести или возобновить лицензию;
- позволять вернуться в Обзор;
- не раскрывать реальные детали инцидентов.

Журнал нарушений без лицензии полностью недоступен и не должен показывать даже ограниченный список событий.

### NEW-LIC-009. Сервисы, недоступные без лицензии

Для состояний «Лицензии никогда не было», «Льготный период закончился» и «Неизвестный статус без достоверной истории» запрещены:

- выгрузка CSV;
- формирование PDF по инциденту;
- массовый поиск;
- ежедневные уведомления;
- просмотр списка и карточек инцидентов;
- просмотр Необходимых действий и Аналитики;
- изменение настроек, кроме запуска подключения ЭЦП.

## 5. Ограничения по стране

### NEW-LOC-001. Источник страны

Единственным источником страны установки является нормализованное значение `setmark.country`.

- `RU` включает российскую модель работы и Мониторинг маркировки.
- Корректное значение, отличное от `RU`, считается страной без Честного знака.
- Пустое или некорректное значение нормализуется в `RU` согласно действующему поведению Set Mark.

### NEW-LOC-002. Страна RU

Для `RU` применяется полная матрица лицензирования, включая Мониторинг маркировки, интеграцию с Честным знаком, подключение ЭЦП и усечённый Обзор по данным ЧЗ без лицензии.

### NEW-LOC-003. Страна не RU

При корректной стране, отличной от `RU`:

- Мониторинг маркировки полностью отсутствует;
- не показывается пункт навигации Мониторинга;
- недоступны страницы, прямые ссылки и API Мониторинга;
- не запускаются интеграция с Честным знаком, сбор, обработка и хранение данных Мониторинга;
- не показывается подключение ЭЦП к Честному знаку;
- Обзор Set Mark остаётся верхнеуровневым разделом и использует только агрегаты действующего Журнала нарушений;
- данные Честного знака и Мониторинга в Обзор не попадают;
- Журнал нарушений продолжает работать по правилам лицензирования Set Mark;
- Журнал использует собственные действующие правила локализации.

Ограничение по стране имеет приоритет над лицензией и ролью: наличие лицензии не должно включать Мониторинг в стране не `RU`.

### NEW-LOC-004. Язык интерфейса

Ограничение русским языком относится только к Мониторингу маркировки. Журнал нарушений в других странах сохраняет собственную локализацию Set Mark.

## 6. Права и роли

### NEW-RBAC-001. Видимость продукта

Раздел Set Mark должен быть виден пользователю SetCentrum независимо от наличия лицензии. Лицензия влияет на доступ к функциям и деталям, но не скрывает сам продуктовый раздел.

### NEW-RBAC-002. Право просмотра Журнала

Существующее право просмотра Журнала нарушений Set Mark используется как базовое право доступа к данным Set Mark:

- без этого права Обзор Set Mark недоступен;
- без этого права реальные данные Журнала и Мониторинга недоступны;
- отсутствие права не должно раскрывать количество, содержание или идентификаторы недоступных объектов;
- вместо данных показывается понятное сообщение об отсутствии доступа.

### NEW-RBAC-003. Настройки

Изменять настройки могут только администраторы. Аналитик может видеть разрешённые ему значения, но не изменять их.

Без лицензии администратор может только начать подключение ЭЦП. Остальные настройки должны быть заблокированы.

### NEW-RBAC-004. Рекомендации

Рекомендации:

- формируются системой;
- доступны пользователям с правом просмотра деталей;
- предназначены только для чтения;
- не имеют редактора в MVP;
- не превращаются автоматически в задачи и не назначаются ответственным.

## 7. Информационная архитектура

### NEW-IA-001. Set Mark в SetCentrum

Set Mark должен отображаться в SetCentrum как самостоятельный продуктовый раздел по аналогии с Set Loyalty.

На верхнем уровне Set Mark располагаются четыре равноправных раздела:

1. Обзор.
2. Журнал нарушений.
3. Мониторинг маркировки.
4. Настройки.

Внутри Мониторинга маркировки располагаются:

1. Инциденты.
2. Необходимые действия.
3. Аналитика.

Обзор и Настройки не должны быть вложены внутрь Мониторинга.

### NEW-IA-002. Журнал нарушений

Действующая визуализация Журнала нарушений должна быть перенесена непосредственно в SetCentrum. Перенос не означает автоматического изменения бизнес-логики Журнала.

Детальная техническая миграция старой визуализации, URL и пользовательского состояния вынесена в отдельную задачу — см. раздел 11.

### NEW-IA-003. Кассы требуют внимания

Функция «Кассы требуют внимания» сохраняется в Настройках. Внутри неё данные должны группироваться в иерархии:

`Магазин → Касса → выявленное расхождение или проблема настройки`.

## 8. Визуальные требования

### NEW-UI-001. Приоритет источников интерфейса

Для разных частей решения применяются разные визуальные эталоны:

1. Оболочка, боковое меню и продуктовая навигация — действующий SetCentrum.
2. Журнал нарушений, его таблицы и фильтры — действующая визуализация Журнала нарушений.
3. Новые экраны Мониторинга маркировки — компоненты и визуальный язык CSI UI.

Это решение заменяет более раннее требование использовать frontend Set Mark как основу всей оболочки.

### NEW-UI-002. Боковое меню

Боковое меню должно визуально соответствовать действующему SetCentrum. Set Mark размещается рядом с Set Loyalty как отдельный продукт. Используются оригинальные логотипы SetRetail10, Set Loyalty и SetMark с сохранением пропорций.

В автономном демонстрационном прототипе пункты, не относящиеся к Set Mark, могут быть безопасными заглушками, но должны воспроизводить визуальный контекст текущего меню.

### NEW-UI-003. Поведение предупреждений

Предупреждения о лицензии должны:

- отличаться от ошибок доступа;
- объяснять конкретное состояние: несоответствие, льготный период или невозможность проверить лицензию;
- при льготном периоде показывать оставшийся срок;
- не блокировать функции в состояниях полного доступа;
- содержать предложение докупить или обновить лицензию, когда это применимо.

## 9. Сбор и хранение данных

### NEW-DATA-001. Продолжение поступления данных

Если сам продукт Set Mark установлен и настроен, записи могут продолжать поступать и накапливаться при отсутствии пользовательского доступа по лицензии. Ограничение лицензии закрывает детализацию, но само по себе не останавливает допустимый сбор данных для RU.

Для страны не `RU` действует исключение: сбор данных Мониторинга и интеграция с Честным знаком вообще не запускаются.

### NEW-DATA-002. Срок хранения

Верхняя граница истории Мониторинга составляет 30 дней. Фактический срок хранения равен меньшему значению из:

- 30 дней;
- настроенного срока хранения Set Mark.

Настройка может только уменьшать срок относительно 30 дней и не может его увеличивать.

### NEW-DATA-003. Исчисление и удаление

- Срок хранения отсчитывается от текущего календарного дня.
- Данные старше доступного срока физически удаляются.
- Удалённые данные не восстанавливаются после покупки или возобновления лицензии.
- После восстановления доступа пользователь видит только фактически сохранившуюся историю.

## 10. Подключение ЭЦП в демо-версии

### NEW-ECP-001. Доступ без лицензии

Администратор RU должен иметь возможность начать подключение ЭЦП даже при отсутствии лицензии Set Mark. Интерфейс должен показывать порядок подключения и корректно объяснять следующий шаг.

### NEW-ECP-002. Ограничение текущей демонстрации

В текущей демо-версии проверяется только:

- наличие точки входа в подключение ЭЦП без лицензии;
- доступность этой точки входа только администратору;
- понятное объяснение следующего шага.

Не требуется фактически выполнять подключение или проверять полный жизненный цикл сертификата.

## 11. Явно отложенные требования

### DEFERRED-001. Полный жизненный цикл ЭЦП

В отдельную последующую задачу вынесены:

- роли и дополнительные права на операции с ЭЦП;
- состояния подключения;
- проверка срока действия сертификата;
- замена и отзыв;
- ошибки авторизации;
- аудит операций;
- безопасное хранение ключей и сертификатов;
- восстановление после ошибок подключения.

### DEFERRED-002. Миграция Журнала в SetCentrum

В отдельную последующую задачу вынесены:

- сохранение или изменение старых URL;
- перенаправления;
- пользовательские закладки;
- перенос сохранённых фильтров;
- сохранение модели прав;
- интеграционные ссылки на старую визуализацию;
- порядок отключения прежней визуализации;
- обратная совместимость внешних переходов.

Эти два блока не являются критериями приёмки текущей демо-версии.

## 12. Повторно подтверждённые функции, включаемые в переносимый набор

Требования этого раздела существовали ранее, но были повторно подтверждены после 28.08 и необходимы для полноты переносимого решения.

### NEW-FR-001. Точный множественный поиск

Список инцидентов поддерживает поиск по:

- штрихкоду;
- артикулу товара;
- полному коду маркировки.

В одном поле можно указать несколько значений разных типов через запятую. Пробелы вокруг значений игнорируются. Значения объединяются по логике «ИЛИ». Для каждого штрихкода, артикула и полного кода маркировки используется точное совпадение.

Массовый поиск недоступен в ограниченном режиме без лицензии.

### NEW-FR-002. Множественный выбор магазинов

Пользователь может выбрать один или несколько магазинов. При выборе нескольких магазинов показывается объединённая выборка. Доступны команды «Выбрать все» и «Сбросить».

Фильтр магазинов применяется совместно с периодом, поиском и остальными фильтрами. Одновременно включённые фильтры объединяются по логике «И» между группами условий.

### NEW-FR-003. Поля товара и операции

Инцидент должен содержать и использовать в карточке, поиске и экспорте:

- штрихкод;
- артикул;
- наименование товара;
- номер чека или идентификатор операции;
- источник проверки.

Эти поля должны относиться к той же операции, что код маркировки и временная метка инцидента.

### NEW-FR-004. CSV текущей выборки

CSV формируется только по текущей выборке и содержит 23 колонки в следующем порядке:

1. ID инцидента.
2. Код правила.
3. Дата и время операции.
4. Магазин.
5. Город.
6. Касса.
7. Штрихкод.
8. Артикул.
9. Наименование товара.
10. Товарная группа.
11. Полный код маркировки.
12. Тип нарушения.
13. Описание исходного отклонения.
14. Результат проверки.
15. Критичность.
16. Риск автоштрафа.
17. Потенциальная сумма штрафа.
18. Установленная причина.
19. Рекомендуемое действие.
20. Контур устранения.
21. Статус анализа.
22. Номер чека или идентификатор операции.
23. Источник проверки.

Файл формируется в UTF-8. Текстовые значения должны корректно экранировать русские символы, запятые, точки с запятой и кавычки.

CSV недоступен в ограниченном режиме без лицензии.

### NEW-GOAL-001. Приоритет бизнес-цели

Главная бизнес-цель функции формулируется как снижение риска штрафов через:

1. первоочередный разбор критических инцидентов, для которых возможен автоштраф;
2. последующее регулярное снижение общего количества нарушений.

## 13. Приоритеты применения требований

При вычислении доступности система должна последовательно применять правила:

1. Нормализовать `setmark.country`.
2. Применить ограничение страны. Для не `RU` Мониторинг отсутствует независимо от лицензии.
3. Проверить право просмотра Журнала. Без него Обзор и реальные данные недоступны.
4. Определить состояние лицензии с учётом последней достоверной истории.
5. Применить приоритет истечения лицензии над лицензионным несоответствием.
6. Определить полный или ограниченный набор функций.
7. Проверить роль администратора перед разрешением изменения настроек.

Такая последовательность обязательна, чтобы одинаковые входные данные давали одинаковый результат в UI, API и фоновых процессах.

## 14. Критерии приёмки

### AC-NEW-001. Полная матрица

Должны быть проверены комбинации:

- страна `RU` и корректная страна не `RU`;
- действующая лицензия;
- лицензионное несоответствие;
- льготный период;
- лицензии никогда не было;
- льготный период закончился;
- неизвестный статус с достоверной историей;
- неизвестный статус без достоверной истории;
- администратор;
- аналитик;
- пользователь без права просмотра ЖН.

Для каждой комбинации проверяются видимость разделов, источник данных Обзора, доступ к деталям, экспортам, уведомлениям, ЭЦП и настройкам.

### AC-NEW-002. Ограниченный режим RU

Для состояний без полного доступа при `RU` проверяется, что:

1. Set Mark остаётся видимым.
2. Обзор доступен пользователю с правом ЖН.
3. Обзор содержит только агрегаты отклонений ЧЗ.
4. Агрегаты Журнала не смешиваются с данными ЧЗ.
5. Журнал недоступен.
6. Инциденты, Необходимые действия и Аналитика открывают лицензионные заглушки.
7. CSV, PDF, массовый поиск и ежедневные уведомления недоступны.
8. Администратор может начать подключение ЭЦП.
9. Остальные настройки изменить нельзя.

### AC-NEW-003. Страна не RU

Проверяется, что:

1. Пункт Мониторинга отсутствует в навигации.
2. Прямые ссылки и API Мониторинга недоступны.
3. Интеграция с ЧЗ и фоновые процессы Мониторинга не запускаются.
4. Подключение ЭЦП к ЧЗ не предлагается.
5. Обзор использует только агрегаты действующего Журнала.
6. Журнал продолжает следовать общей лицензии Set Mark и собственной локализации.

### AC-NEW-004. Неизвестное состояние лицензии

- При наличии истории доступ точно совпадает с последним достоверным состоянием, дополнительно показывается предупреждение.
- При отсутствии истории доступ совпадает с состоянием «Лицензии никогда не было», дополнительно показывается предупреждение.

### AC-NEW-005. Льготный период и сессия

Проверяется граница десятого календарного дня в часовом поясе SetCentrum. До границы доступ полный, после границы новая сессия получает ограниченный доступ. Открытая до границы сессия не меняется автоматически.

### AC-NEW-006. Хранение

Проверяется, что срок не превышает 30 дней, пользовательская настройка может его сократить, устаревшие записи физически удаляются и не появляются после возобновления лицензии.

### AC-NEW-007. Поиск и экспорт

Проверяется:

1. поиск по одиночному штрихкоду;
2. поиск по одиночному артикулу;
3. поиск по полному коду маркировки;
4. смешанный запрос через запятую по логике «ИЛИ»;
5. множественный выбор, выбор всех и сброс магазинов;
6. совместная работа фильтров;
7. наличие 23 колонок CSV в установленном порядке;
8. выгрузка только текущей выборки;
9. корректное UTF-8 и экранирование.

## 15. Рекомендации по переносу в другой проект

Перед применением набора в другом продукте необходимо заменить только проектно-зависимые элементы:

- название лицензии Set Mark;
- название оболочки SetCentrum;
- источник страны `setmark.country`;
- название внешней системы Честный знак;
- существующее право просмотра Журнала;
- роли администратора и аналитика;
- источник достоверного состояния лицензии Set Agent;
- конкретные визуальные библиотеки и логотипы.

При переносе нельзя без отдельного решения менять:

- правило «одна лицензия на оба раздела»;
- десятидневный календарный льготный период;
- приоритет страны, прав и истечения лицензии;
- источник данных усечённого Обзора;
- физическое удаление истории старше доступного срока;
- недоступность деталей и экспортов без лицензии;
- разграничение полного жизненного цикла ЭЦП и его демонстрационной точки входа.

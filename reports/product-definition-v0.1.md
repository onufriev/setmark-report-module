# Контрольный отчёт: PRODUCT_DEFINITION

**Продукт:** модуль отчёта по нарушениям Set Mark  
**Статус:** Готово к проверке Product Manager  
**Дата:** 2026-07-28

## Суть этапа

Определён MVP функции централизованного мониторинга нарушений маркировки внутри Set Mark. Зафиксированы цели и границы, пользователи и права, модель объектов и инцидентов, правила анализа `RA-01–RA-05`, интерфейсные сценарии, интеграции, данные, качество, исключительные и эксплуатационные сценарии, критерии приёмки и трассировка.

Функция помогает аналитикам находить магазины, кассы и виды нарушений с наибольшим риском, переходить к инцидентам, понимать причину результата анализа и определять дальнейшие действия. Назначение ответственных, постановка задач и контроль устранения не входят в MVP.

## Пользователи и основные сценарии

- Аналитик по работе с маркировкой просматривает обзор сети и определяет объекты с наибольшим риском или накоплением нарушений.
- Пользователь переходит от сети, магазина, кассы, товарной группы или вида нарушения к отфильтрованному списку инцидентов.
- В карточке инцидента доступны исходные данные, результат `RA-01–RA-05`, объяснение, критичность, риск, Контур устранения и рекомендация.
- Выбранный контекст сохраняется при возврате к списку и аналитике; текущую выборку можно выгрузить в CSV.
- Настроенные получатели получают ежедневные уведомления о критичных нарушениях.
- Администратор управляет подключением функции, получателями уведомлений и сроком хранения данных.

## Границы MVP

- Функция поставляется как часть Set Mark и использует его аутентификацию, права, обновление, восстановление и эксплуатационные механизмы.
- Один внешний факт отклонения создаёт один инцидент; повторная доставка не создаёт дубликат.
- Сбои функции не влияют на продажи и проверку кодов.
- Неполные, устаревшие и неизвестные данные показываются с явными ограничениями и обрабатываются по утверждённым правилам.
- Управление задачами, назначение ответственных и контроль фактического устранения находятся вне MVP.

## Данные и интеграции

- Отклонения поступают через существующую интеграцию Set Mark с Честным знаком.
- Для анализа используются доступные в Set Mark кассовые операции, результаты онлайн- и офлайн-проверок и настройки.
- Исходный снимок события сохраняется; время операции и регистрации нормализуется с сохранением исходных значений.
- Источник рабочего прототипа определён решением `PM-DEC-028`: воспроизводимый набор синтетических файлов на основе структуры предоставленного отчёта Честного знака.
- Клиентский Excel используется только как локальный образец структуры, не сохраняется в репозитории и не переносится в демонстрационный набор.
- Все идентификаторы генерируются заново, распределения балансируются для демонстрации, а seed/reset-скрипты и автоматическая проверка должны подтверждать связи, покрытие `RA-01–RA-05` и отсутствие реальных клиентских идентификаторов.

## Критерии качества и приёмки

- Основные экраны открываются не более чем за 3 секунды для 95% запросов.
- Инцидент появляется не позднее 24 часов после доступности исходных данных.
- Обзор показывает период, свежесть, полноту данных, показатели и объекты с наибольшим риском.
- Аналитика, фильтры, пороги, CSV и уведомления используют согласованные данные.
- После сбоя обработка автоматически продолжается без потери исходных событий.
- Пользователь на демонстрационных данных без дополнительных объяснений может найти приоритетный объект, открыть инцидент, понять результат и рекомендацию, корректно интерпретировать ограничения данных и выгрузить выборку.

## Трассировка

Требования связаны с семью проверяемыми частями решения: обзором сети, списком инцидентов и фильтрами, карточкой инцидента, аналитикой и CSV, ежедневными уведомлениями, настройками функции, исключительными и эксплуатационными сценариями. Для сценариев, экранов и критериев проверки используются канонические `REQ-*`; каждое требование MVP имеет подтверждённое основание `SRC-EV-*` или `PM-DEC-*`.

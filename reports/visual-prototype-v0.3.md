# Контрольный отчёт: VISUAL_PROTOTYPE

**Продукт:** модуль отчёта по нарушениям Set Mark  
**Редакция:** R3  
**Статус:** Готово к проверке Product Manager  
**Дата:** 2026-08-31

## Суть этапа

После ручного сравнения Product Manager с предыдущей версией прототипа в `VISUAL_PROTOTYPE-R2` были обнаружены функциональные регрессии, возникшие при упрощении `app.js` 31 июля. R3 восстанавливает ранее согласованные функции без отката более поздних улучшений поиска, фильтра магазинов, CSV, данных товара и расчёта потенциального штрафа.

Дополнительно автоматическая проверка визуального прототипа усилена так, чтобы повторное исчезновение ключевых блоков и переходов останавливало проверку артефакта.

## Исправленные регрессии

### Дашборд

- Восстановлен блок «Объекты с наибольшим риском» с сортировкой по критическим инцидентам.
- Восстановлен переход из объекта риска к соответствующим критическим инцидентам магазина.
- Восстановлен блок «Состояние данных» ровно с двумя согласованными сигналами: последнее обращение за отчётом Честного Знака и связь с Set Centrum.
- Четыре агрегированных показателя сделаны переходами к соответствующей выборке инцидентов.
- Показатель «Подтверждённые нарушения» рассчитывается по выбранному периоду.
- Диаграмма типов нарушений рассчитывается по выбранному периоду.
- Необходимые действия и количество связанных с ними инцидентов пересчитываются по выбранному периоду.

### Аналитика

- Восстановлены фильтры «Только критические» и «Только подтверждённые нарушения»; они могут применяться совместно.
- Восстановлены показатели «Инциденты», «Критические», «Подтверждённые нарушения» и «Группировка».
- Сохранена автоматическая группировка: до 14 дней включительно — по дням, более длительный период — по неделям.
- Для недель показывается полный диапазон дат группы.
- Столбцы графика снова кликабельны и открывают ровно инциденты соответствующего дня или недели.

### Инциденты и карточка

- Сохранены поиск по штрихкоду, артикулу и полному коду маркировки, несколько значений через запятую и множественный фильтр магазинов.
- Восстановлено сохранение фокуса при поиске.
- Восстановлена проверка произвольного периода: обе даты обязательны, дата начала не может быть позже даты окончания.
- В пустой выборке восстановлена кнопка сброса фильтров.
- Строки инцидентов снова открываются с клавиатуры.
- Кнопка «Копировать ссылку» имеет рабочий обработчик.
- Кнопка PDF теперь загружает реальный PDF конкретного демонстрационного инцидента.

### Настройки

- Восстановлен блок ежедневных уведомлений.
- Восстановлена настройка срока хранения данных.

## Потенциальный штраф

Потенциальный штраф сохранён в пользовательском интерфейсе и не включён в CSV или PDF.

Для агрегированного показателя используется отдельная функция расчёта, которая учитывает одну нормативную группу один раз. Это исключает повторное суммирование одного штрафного риска для связанных инцидентов накопительного состава. Для текущих демонстрационных данных критические инциденты независимы, поэтому каждый учитывается отдельно.

## PDF

Для девяти демонстрационных инцидентов PDF формируется перед публикацией GitHub Pages из актуальных данных прототипа.

PDF содержит сведения об инциденте, операции, товаре, полном коде маркировки, исходном отклонении и результате анализа. В PDF не включаются потенциальная сумма штрафа, рекомендации по устранению и подпись.

## Сохранённые улучшения R2

- Готовые и произвольный диапазоны дат.
- Поиск по штрихкоду, артикулу и полному коду маркировки с несколькими значениями через запятую.
- Множественный выбор магазинов, «Выбрать все» и «Сбросить».
- Расширенные данные товара и операции.
- CSV текущей выборки из 21 согласованного поля.
- Отсутствие отдельного признака «Риск автоштрафа» в CSV и карточке.
- Потенциальный штраф в Дашборде, списке и карточке.
- Денежные значения без символа валюты.
- Точный расчёт штрафа и запрет двойного учёта накопительных составов.

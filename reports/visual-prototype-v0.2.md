# Контрольный отчёт: VISUAL_PROTOTYPE

**Продукт:** модуль отчёта по нарушениям Set Mark  
**Редакция:** R2  
**Статус:** Готово к проверке Product Manager  
**Дата:** 2026-08-31

## Суть этапа

Визуальный прототип функции мониторинга и анализа нарушений маркировки внутри Set Mark приведён в соответствие с актуальными требованиями и решениями Product Manager.

После замечаний к R1 добавлен произвольный диапазон дат на вкладках «Дашборд» и «Инциденты». Дополнительно синхронизированы изменения, появившиеся после первого review: расширенный поиск, множественный выбор магазинов, состав CSV, данные товара и операции, логика потенциального штрафа и два основных пользовательских режима.

Коммерческая модель и объект продажи функции в текущем MVP не определяются и не ограничивают прототип.

## Основные пользовательские пути

### Критический контроль

1. Пользователь открывает Дашборд и выбирает готовый или произвольный период.
2. Сразу видит наличие критических инцидентов, для которых возможен автоштраф.
3. Переходит к соответствующей выборке инцидентов.
4. Открывает карточку и видит причину, результат проверки, критичность, потенциальный штраф, Контур устранения и рекомендацию.
5. Определяет необходимое действие; фактическое устранение выполняется вне функции.

### Регулярное снижение нарушений

1. При отсутствии критических инцидентов пользователь оценивает необходимые действия.
2. Действия приоритизируются по количеству связанных инцидентов, а предотвращающие критические инциденты всегда находятся выше остальных.
3. Пользователь переходит к связанным инцидентам и уточняет причины через поиск, фильтры, карточки и аналитику.
4. Цель — снижать общее количество нарушений и связанный регуляторный риск.

## Изменения после VISUAL_PROTOTYPE-R1

- Добавлен вариант периода «Произвольный» с датами начала и окончания на Дашборде и в Инцидентах.
- Поиск поддерживает штрихкод, артикул и полный код маркировки; несколько значений через запятую объединяются по логике ИЛИ, совпадение точное.
- Фильтр магазинов поддерживает множественный выбор, «Выбрать все» и «Сбросить».
- В карточку и данные инцидента добавлены штрихкод, артикул, наименование товара, номер чека/идентификатор операции и источник проверки.
- CSV формируется по текущей выборке и содержит 21 согласованную колонку.
- В CSV отсутствуют отдельный признак «Риск автоштрафа» и потенциальная сумма штрафа; риск выражается через критичность.
- Потенциальный штраф сохранён в пользовательском интерфейсе как важный показатель оценки риска: на Дашборде, в списке и карточке инцидента.
- Денежные значения отображаются без символа валюты.
- Потенциальный штраф рассчитывается по точной формуле применимой нормы.
- Для накопительных составов штраф считается один раз на нормативный объект и нормативный период; связанные инциденты не создают повторного суммирования одного штрафа.
- При поступлении новых данных в накопительном составе текущий потенциальный штраф пересчитывается по достигнутому порогу.

## Ключевые решения Product Manager

- `PM-DEC-051` — поиск, множественный фильтр магазинов и расширенные данные инцидента.
- `PM-DEC-052` — коммерческая модель и объект продажи не определяются в текущем MVP.
- `PM-DEC-053` — состав CSV: 21 поле без отдельного риска автоштрафа и без суммы потенциального штрафа.
- `PM-DEC-054` — потенциальный штраф остаётся в интерфейсе как показатель риска.
- `PM-DEC-055` — точный расчёт потенциального штрафа по применимой норме.
- `PM-DEC-056` — отсутствие двойного учёта для накопительных составов.

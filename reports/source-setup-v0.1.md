# Контрольный отчёт: SOURCE_SETUP

**Продукт:** модуль контроля нарушений Set Mark  
**Статус:** Готово к проверке Product Manager  
**Дата:** 2026-07-28

## Суть этапа

Настройка источников завершена в режиме `MIXED`. Зарегистрированы проверяемые локальные снимки исходной постановки, внутренней документации Set Mark / SetRetail и справочников отклонений True API v704.0.

Из доступных источников извлечены точные выдержки и начат перенос подтверждённых сведений в канонические требования. Полнота требований ещё не установлена: 25 областей или частных решений остаются в состоянии `NEEDS_INPUT`.

## Что подтверждено

- Проблема позднего обнаружения нарушений и назначение централизованного мониторинга — `SRC-EV-001`, `SRC-EV-002`.
- Контекст Set Mark как модуля экосистемы Set Retail 10 — `SRC-EV-011`.
- Агрегированный мониторинг, CSV и ежедневные уведомления — `SRC-EV-003`–`SRC-EV-005`.
- Получение отклонений True API и корреляция с журналом Set Mark — `SRC-EV-006`, `SRC-EV-007`, `SRC-EV-012`.
- Исходные качественные требования по производительности, масштабу и надёжности — `SRC-EV-008`–`SRC-EV-010`; числовые критерии пока не подтверждены.
- Контекст онлайн- и последующей офлайн-проверки разрешительного режима — `SRC-EV-013`–`SRC-EV-015`.
- Справочники категорий, видов и результатов отклонений True API v704.0 — `SRC-EV-016`.
- Все розничные отклонения входят в область продукта независимо от контура устранения — `PM-DEC-001`.
- Поле области устранения называется «Контур устранения» — `PM-DEC-002`.

## Что пока не подтверждено

- Полный состав MVP и явные исключения.
- Роли и права доступа.
- Пользовательские, системные, исключительные и эксплуатационные сценарии.
- Измеримые нефункциональные критерии.
- Локализация, доступность и оборудование.
- Источник UI и критерии приёмки.
- Национальный средний объём реализации и признак обращения к ГИС МТ остаются неблокирующими открытыми вопросами нормативной модели.
- Официальные нормативные акты перечислены в рабочем нормативном реестре, но их локальные снимки ещё не зарегистрированы как доказательства Product Compiler из-за недоступности официальных страниц при текущем получении. Нормативные требования нельзя считать формально подтверждёнными до регистрации снимков.

## Блокировки

- Переход к визуальному прототипу заблокирован: gate `VISUAL_PROTOTYPE` имеет статус `BLOCKED`, открыто 25 `NEEDS_INPUT`.
- Переход к следующему этапу процесса требует отдельного утверждения этого отчёта Product Manager.

## Что изменилось в requirements/

- Добавлены 20 подтверждённых требований в областях продуктового контекста, цели, функции, бизнес-объекты, бизнес-правила, качество, интеграции и данные.
- Сохранены общие `NEEDS_INPUT`; подтверждённые выдержки не использованы для автоматического закрытия неизвестных частей областей.
- Решения о границе розничного каталога и термине «Контур устранения» перенесены в требования через `PM-DEC-001` и `PM-DEC-002`.
- Baseline требований не зафиксирован: полнота gate `VISUAL_PROTOTYPE` ещё не достигнута.

## Внутренние противоречия

- Открытые `BLOCKER`: нет.
- Открытые `MAJOR`: нет.
- Статус исходной постановки «Черновик» сохранён как ограничение силы источника.

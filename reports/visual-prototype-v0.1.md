# Контрольный отчёт: VISUAL_PROTOTYPE

**Продукт:** модуль отчёта по нарушениям Set Mark  
**Редакция:** R1  
**Статус:** Готово к проверке Product Manager  
**Дата:** 2026-07-28

## Суть этапа

Создан локальный кликабельный визуальный прототип модуля мониторинга нарушений маркировки внутри Set Mark. Прототип использует подтверждённую стратегию `COMPONENT_LIBRARY`: визуальный язык библиотеки `@crystalservice/csi_ui` и актуального frontend Set Mark воспроизведён в самостоятельном статическом приложении без backend и реальных интеграций.

Главный путь начинается с обзора сети и сразу направляет внимание пользователя на критические инциденты с установленным риском выставления автоштрафа. Из приоритетного блока пользователь переходит к отфильтрованному списку, открывает карточку инцидента и видит раздельно исходные признаки онлайн Честного знака, решение кассового ПО и фактическое действие кассы.

Все демонстрационные магазины, кассы, операции, коды маркировки и идентификаторы синтетические. Клиентский Excel и реальные клиентские данные в прототип не включены.

## Обязательный пользовательский путь

1. Обзор сети.
2. Критические инциденты с риском автоштрафа.
3. Список инцидентов с автоматически включённым приоритетным фильтром.
4. Карточка инцидента `INC-10482`.
5. Аналитика и выгрузка текущей выборки в CSV.

Дополнительно доступны:

- фильтрация и поиск по магазину, кассе, нарушению и идентификатору;
- сохранение фильтров при переходе в карточку и обратно;
- результаты `RA-01`–`RA-05`;
- состояние и полнота источников данных;
- настройки новой будущей интеграции Set Mark с API Честного знака;
- ежедневные уведомления и срок хранения;
- пустое состояние и сброс фильтров;
- адаптивная навигация для телефона.

## Ключевые продуктовые решения в интерфейсе

- Критические инциденты с риском автоштрафа находятся выше общих показателей и доступны без предварительной настройки фильтров — `PM-DEC-030`.
- Ответ онлайн Честного знака показан как набор исходных признаков, а не как готовое разрешение или запрет продажи — `PM-DEC-031`.
- Решение кассового ПО и фактическое действие кассы показаны отдельными последовательными шагами — `PM-DEC-031`.
- Прототип не предполагает существующей интеграции Set Mark с Честным знаком: отдельно названа новая будущая интеграция Set Mark с API Честного знака для получения отклонений — `PM-DEC-032`.
- Назначение ответственных, постановка задач и статусы устранения отсутствуют в интерфейсе согласно границам MVP — `PM-DEC-010`, `PM-DEC-023`.

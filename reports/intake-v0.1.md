# Контрольный отчёт: INTAKE

**Продукт:** модуль контроля нарушений Set Mark  
**Статус:** Готово к проверке Product Manager  
**Дата:** 2026-07-28

## Суть этапа

Обработаны доступные материалы и выполнено первичное извлечение продуктовых сведений. Найдены подтверждённые сведения о назначении продукта, функциях мониторинга, интеграции с True API, отдельных бизнес-правилах, данных и качественных характеристиках.

Полнота требований ещё не установлена. Выявлены области, требующие решения Product Manager или дополнительных источников; они сохранены как явные `NEEDS_INPUT`. Допустимый источник UI в доступных материалах не найден и не выбран.

## Результат этапа

- Обработано 6 зарегистрированных источников.
- Зарегистрировано 16 доказательств из источников `SRC-EV-001`–`SRC-EV-016`.
- Зарегистрировано 2 решения Product Manager `PM-DEC-001` и `PM-DEC-002`.
- Извлечено 20 подтверждённых требований: 18 из источников и 2 из решений Product Manager.
- Выявлено 25 открытых вопросов в 25 областях или частных решениях.
- Кандидаты допустимого источника UI не обнаружены.

## Что подтверждено

- Проблема позднего обнаружения нарушений и назначение централизованного мониторинга — `SRC-EV-001`, `SRC-EV-002`.
- Контекст Set Mark как модуля экосистемы Set Retail 10 — `SRC-EV-011`.
- Агрегированный мониторинг, выгрузка CSV и ежедневное информирование о критичных нарушениях — `SRC-EV-003`–`SRC-EV-005`.
- Получение отклонений через True API и корреляция с журналом Set Mark — `SRC-EV-006`, `SRC-EV-007`, `SRC-EV-012`.
- Исходные качественные характеристики производительности, масштабируемости и надёжности — `SRC-EV-008`–`SRC-EV-010`; измеримые значения пока не подтверждены.
- Контекст онлайн- и офлайн-проверки разрешительного режима — `SRC-EV-013`–`SRC-EV-015`.
- Справочники категорий, видов и результатов отклонений True API v704.0 — `SRC-EV-016`.
- Все отклонения розничной реализации и выбытия входят в область продукта независимо от контура устранения — `PM-DEC-001`.
- Классификационное поле области корректирующего действия называется «Контур устранения» — `PM-DEC-002`.

## Что пока не подтверждено

- Полный состав MVP и явные исключения.
- Иерархия объектов продаж.
- Роли и права доступа.
- Полный каталог бизнес-правил, состояний и ошибок.
- Пользовательские, системные, исключительные и эксплуатационные сценарии.
- Измеримые нефункциональные критерии.
- Локализация, доступность и требования к оборудованию.
- Критерии приёмки и сигнал успешной проверки прототипа.
- Допустимый источник UI: Figma, библиотека компонентов или Storybook.
- Трассировка требований и технические ограничения прототипа.
- Источник национального среднего объёма реализации и наличие в True API признака обращения к ГИС МТ; эти вопросы остаются неблокирующими для перехода к `PRODUCT_DEFINITION`.

## Блокировки

- Переход к `VISUAL_PROTOTYPE` заблокирован: gate имеет статус `BLOCKED`.
- Открыто 25 вопросов `NEEDS_INPUT`.
- Baseline требований не зафиксирован.
- Переход к `PRODUCT_DEFINITION` требует отдельного утверждения этого отчёта Product Manager.

## Что изменилось в requirements/

- В ходе извлечения сформировано 20 подтверждённых требований в восьми областях: продуктовый контекст, цели и границы, функциональные требования, бизнес-объекты, бизнес-правила, качество, интеграции и данные.
- В каждой неполной области сохранён явный `NEEDS_INPUT`; подтверждённые фрагменты не использованы для автоматического закрытия неизвестных частей.
- Требования не фиксировались в baseline, поскольку gate `VISUAL_PROTOTYPE` ещё не пройден.

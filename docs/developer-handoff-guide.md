# Передача в разработку

Каталог `handoff/` предназначен только для чтения архитектором, лидом и
разработчиком. Его первым файлом является `handoff/DEVELOPER-START-HERE.md`.
Это производное представление, а не источник требований: Product Compiler и другие
агенты не используют `handoff/` для извлечения фактов, проверки полноты или изменения
канонических требований.

Перед регистрацией handoff Product Compiler обязан скомпилировать в
`handoff/requirements/` понятную человеку картину продукта из `requirements/`:

Для этой компиляции на этапе `HANDOFF_READY` обязательно применяется локальный skill
`$product-handoff-compiler` («Сформировать итоговые материалы»), который включён в
репозиторий по пути `.codex/skills/product-handoff-compiler/`.

- продукт, домен, границы MVP, объекты, роли, состояния и бизнес-правила;
- функциональные требования, данные и интеграции;
- пользовательские, бизнес-, системные, исключительные и эксплуатационные сценарии;
- нефункциональные требования, локализация, доступность, оборудование и технические ограничения;
- критерии приёмки и трассировка.

Основной handoff не должен требовать от человека чтения базовой версии требований,
реестров, контрольных отчётов или поиска решений менеджера продукта. Канонические
`REQ-*` сохраняются только для трассировки и перехода к источнику при спорной детали.

Материалы прототипирования в handoff не включаются. Стек, производственная архитектура и источники производственных данных передаются как зона ответственности команды разработки.

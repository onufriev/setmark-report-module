# Правило анализа INC-001 v0.1

**Инцидент:** Повторные продажи у одного продавца более или равно 30 минут  
**Код True API:** категория `11`, вид `24`, результат `36`  
**Статус:** согласовано Product Manager  
**Дата решения:** 2026-07-30  
**Связанные артефакты:** [Каталог инцидентов v0.1](../incident-catalog-v0.1.md), [Модель необходимых действий v0.1](../necessary-action-model-v0.1.md)

## 1. Назначение

Правило определяет анализ инцидента, сформированного по отклонению Честного знака «Повторные продажи у одного продавца более или равно 30 минут», и автоматическое формирование необходимых действий.

Факт получения отклонения Честного знака создаёт инцидент, но сам по себе не определяет его фактическую причину. Для одного инцидента фактическая причина считается единственной. Если доступных данных недостаточно для её достоверного определения, система фиксирует статус `Причина не определена достоверно` и формирует предусмотренные правилом возможные действия.

## 2. Необходимые данные

Для анализа используются:

- код маркировки;
- дата и время отклонения Честного знака;
- связанные продажи этого кода маркировки в SetRetail;
- возвраты этого кода маркировки в SetRetail между первой и повторной продажей;
- магазины, в которых выполнены продажи;
- схема развёртывания Set Mark Centrum: централизованный экземпляр либо отдельные экземпляры в магазинах;
- состояние проверки товарной категории в Set Mark;
- сведения о доступности Set Mark при выполнении продаж;
- настройка, разрешающая продажу маркированного товара при недоступности Set Mark.

Система не обязана дополнительно искать ещё одну продажу того же кода маркировки после найденного корректного возврата. Проверка такой дополнительной продажи не входит в правило v0.1.

## 3. Определение нарушающей операции

Если в SetRetail найдены две продажи одного кода маркировки, между ними нет возврата и Честный Знак передал отклонение, вторая продажа считается подтверждённой нарушающей операцией.

Если Честный Знак передал несколько отклонений для последовательности из трёх и более продаж, каждая повторная продажа, для которой передано отдельное отклонение, создаёт отдельный инцидент.

## 4. Ветка A: между продажами найден успешный возврат

### 4.1. Результат анализа

Последовательность `Продажа → успешный возврат в SetRetail → повторная продажа` по данным SetRetail не подтверждает нарушение со стороны торговой сети. При этом Честный Знак всё равно зафиксировал отклонение.

Система не утверждает, что возврат дошёл до внешнего контура только на основании его наличия в SetRetail. Фактическая причина отклонения по доступным данным не определяется достоверно.

Результат:

- статус причины: `Причина не определена достоверно`;
- вывод: повторная продажа после успешного возврата не подтверждена как нарушение торговой сети по данным SetRetail;
- пользователю показываются найденные операции продажи и возврата;
- формируется одно последовательное необходимое действие по проверке чека возврата в ОФД.

### 4.2. Необходимое действие

Пользователь должен найти чек возврата в ОФД и убедиться, что возврат там зафиксирован.

Дальнейшее действие зависит от результата проверки:

1. **Чек возврата отсутствует в ОФД.**  
   Обратиться в техническую поддержку CSI.

2. **Чек возврата найден в ОФД и корректно зафиксирован, но Честный Знак сформировал отклонение.**  
   Обратиться в техническую поддержку Честного Знака.

Обращение в техническую поддержку ОФД для этого сценария не назначается.

## 5. Ветка B: между продажами нет возврата

### 5.1. Результат анализа

Если две продажи одного кода маркировки подтверждены в SetRetail, между ними отсутствует возврат и отклонение получено от Честного Знака, система устанавливает:

- результат: подтверждённое нарушение;
- нарушающая операция: вторая продажа;
- далее система проверяет возможные причины в порядке, определённом данным правилом.

Наличие нескольких проверяемых вариантов не означает, что у инцидента несколько фактических причин. Система должна установить одну причину, если для неё есть достаточные подтверждающие данные. Если ни одна причина не подтверждена, причина считается не определённой достоверно.

### 5.2. Причина 1: отдельные Set Mark Centrum в разных магазинах

Причина применима, только если:

- первая и повторная продажи выполнены в разных магазинах;
- в магазинах используются отдельные экземпляры Set Mark Centrum;
- централизованный Set Mark Centrum для торговой сети не используется.

Установленная причина:

> Локальный экземпляр Set Mark Centrum не располагал сведениями о продаже, выполненной в другом магазине.

Необходимое действие:

> Перейти с отдельных экземпляров Set Mark Centrum в магазинах на централизованный Set Mark Centrum для торговой сети.

Система не должна предлагать «обеспечить проверку между магазинами» или синхронизацию отдельных экземпляров: такой возможности нет.

### 5.3. Причина 2: отключена проверка товарной категории

Причина применима, если в Set Mark отключена проверка категории, к которой относится проданный товар.

Установленная причина:

> Для товарной категории была отключена проверка в Set Mark, поэтому повторная продажа не была заблокирована.

Необходимое действие:

> Включить проверку соответствующей товарной категории в Set Mark.

Конкретный путь и название параметра должны определяться по поддерживаемой версии SetRetail и Set Centrum. Актуальная настройка не является доказательством того, что такое же значение действовало в момент инцидента, если историческая версия конфигурации недоступна.

### 5.4. Причина 3: продажа при недоступности Set Mark

Причина применима, если одновременно подтверждено:

- одна из продаж выполнена при недоступности Set Mark;
- в конфигурации разрешена продажа маркированных товаров при недоступности Set Mark.

Установленная причина:

> Продажа была завершена без проверки в Set Mark, поскольку при недоступности сервера операция была разрешена настройкой.

Необходимое действие:

> Запретить продажу маркированных товаров при недоступности Set Mark.

Для конкретной версии конфигурации действие должно ссылаться на соответствующий параметр, например `Разрешать операцию, при недоступности сервера`, с целевым значением «выключено».

### 5.5. Ни одна известная причина не подтверждена

Если:

- сценарий с отдельными экземплярами Set Mark Centrum в разных магазинах не применим;
- проверка товарной категории включена;
- продажа при недоступности Set Mark не была разрешена либо такой факт не подтверждён;
- и ни одна другая утверждённая причина правила не установлена,

система фиксирует:

- статус: `Причина не определена достоверно`;
- результат: подтверждённое нарушение с неустановленной причиной;
- необходимое действие: обратиться в техническую поддержку CSI для дополнительной диагностики.

## 7. Ограничения правила v0.1

- Правило не выполняет автоматическую проверку чека возврата в ОФД; это действие выполняет пользователь.
- Правило не проверяет наличие дополнительной продажи после корректного возврата.
- Текущая конфигурация Set Centrum не доказывает историческое значение настройки в момент продажи.
- Правило не предлагает синхронизацию отдельных экземпляров Set Mark Centrum между магазинами, поскольку такой возможности нет.
- Правило не назначает поддержку ОФД как адресата обращения.
- При изменении правила новые условия применяются только к новым инцидентам; существующие инциденты автоматически не пересчитываются.

## 8. Критерии приёмки

1. Для последовательности с успешным возвратом система не объявляет торговую сеть нарушителем только на основании отклонения Честного Знака.
2. При успешном возврате система формирует проверку чека возврата в ОФД.
3. При отсутствии возврата в ОФД система направляет пользователя в техническую поддержку CSI.
4. При наличии корректного возврата в ОФД система направляет пользователя в техническую поддержку Честного Знака.
5. Для двух продаж без возврата вторая продажа определяется как нарушающая.
6. Причина с отдельными Set Mark Centrum применяется только к продажам в разных магазинах.
7. Для этой причины система рекомендует централизованный Set Mark Centrum и не предлагает несуществующую межмагазинную синхронизацию.
8. При отключённой проверке категории система рекомендует включить её.
9. При разрешённой продаже во время недоступности Set Mark система рекомендует запретить такую продажу.
10. Если ни одна причина не подтверждена, система направляет пользователя в техническую поддержку CSI.
11. В одном инциденте система не утверждает наличие нескольких фактических причин.

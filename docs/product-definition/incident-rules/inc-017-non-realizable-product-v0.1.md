# Правило анализа INC-017 v0.1

**Инцидент:** Продажа товара, недоступного для реализации
**Коды True API:** категория `8`; виды `16`, `17`, `20`; результаты `22`, `24`, `28`
**Статус:** согласовано Product Manager
**Основание согласования:** `PM-DEC-108`
**Связанные артефакты:** [Каталог инцидентов v0.1](../incident-catalog-v0.1.md), [Правило INC-001](inc-001-repeat-sales-same-seller-v0.1.md), [Единая ветка доказанного отсутствия результата](../diagrams/proven-no-response-settings-flow-v0.1.svg), [Схема анализа INC-017](../diagrams/inc-017-analysis-flow-v0.1.svg)

## 1. Назначение

INC-017 объединяет розничные продажи товара, для которого результат проверки содержит `realizable=false`: товар ранее выбыл по причине, отличной от розничной продажи, либо отсутствуют сведения о его вводе в оборот.

Поле `sold` проверяется раньше `realizable`. Если `sold=true`, применяется правило повторной продажи INC-001 независимо от значения `realizable`. При `sold=false` до запрета по `realizable=false` проверяется табачное исключение: для табачной продукции при `grayZone=true` продажа разрешена. Только после исключения этого случая применяется обычная проверка `realizable`.

## 2. Необходимые данные

- полный КМ, товарная группа, магазин, касса и чек;
- факт завершения продажи;
- канал проверки и полный сохранённый результат;
- значения `sold`, `grayZone` и `realizable` из результата проверки;
- товарная группа, необходимая для применения исключения серой зоны только к табачной продукции;
- события решения кассового ПО;
- текущая настройка `check.excise.ignoreTrueApiMarkRealizable`;
- доказательства отсутствия результата обоих каналов, если результат проверки не сохранён;
- текущая настройка валидации товарной группы и настройка `Разрешить продажу при отсутствии ответа от ЧЗ`.

## 3. Возможные причины и действия

| Условие | Результат | Причина / статус причины | Необходимое действие |
|---|---|---|---|
| Сохранённый результат содержит `sold=true` | Применить INC-001 | Приоритет имеет запрет повторной продажи | Продолжить анализ по правилу INC-001; не назначать причину по `realizable` |
| Сохранённый результат содержит `sold=false`; товар относится к табачной продукции; `grayZone=true`; `realizable=false` | `RA-02` | Допустимый сценарий: для табачной продукции в серой зоне запрет по `realizable=false` не применяется | Не проверять `check.excise.ignoreTrueApiMarkRealizable` и не назначать кассовое нарушение; показать применённое исключение |
| Сохранённый результат содержит `sold=false`, `realizable=false`; продажа завершена; игнорирование включено | `RA-01` | Настройка разрешила продажу товара, недоступного для реализации | Установить `check.excise.ignoreTrueApiMarkRealizable=false` |
| Сохранённый результат содержит `sold=false`, `realizable=false`; игнорирование уже выключено; продажа завершена | `RA-01` | Обязательная блокировка кассового ПО не сработала | Обратиться в поддержку CSI; передать чек, КМ, канал, полный результат и события решения кассы |
| Сохранённый результат содержит `sold=false`, `realizable=true`, но позднее получен INC-017 | `RA-04` | Сохранённый результат противоречит отклонению | Обратиться в поддержку Честного Знака с отклонением, чеком, КМ и полным результатом |
| Доказано отсутствие результата онлайн ЧЗ и ЛМ ЧЗ; продажа завершена | `RA-01` | Продажа прошла без результата обязательной проверки | Применить единую ветку: проверить валидацию товарной группы, затем запрет продажи без ответа; если обе настройки корректны, обратиться в CSI |
| Исторический результат только не найден либо значения `sold` и `realizable` неизвестны | `RA-04` | Недостаточно данных; отсутствие результата в выборке не доказывает отсутствие проверки | Получить кассовые логи, события решения и сохранённые ответы каналов |

## 4. Ограничения v0.1

- Текущий статус КМ в ГИС МТ не заменяет сохранённый результат на момент продажи.
- `sold=true` всегда маршрутизирует инцидент в INC-001 до анализа `realizable`.
- `grayZone=true` отменяет запрет по `realizable=false` только для табачной продукции и только после исключения `sold=true`.
- `realizable=false` не используется как признак INC-003: INC-003 определяется по `found=false`.
- Текущая конфигурация является возможным фактором, но не доказывает историческое значение настройки без снимка или события на момент продажи.
- Риск автоштрафа устанавливается в `Нет`, пока отдельное действующее нормативное правило не подтверждено.

## 5. Критерии приёмки

1. При `sold=true` система применяет INC-001 и не создаёт конкурирующую причину по `realizable`.
2. При `sold=false`, табачной продукции и `grayZone=true` система применяет `RA-02` и не считает `realizable=false` основанием кассового нарушения.
3. При `sold=false`, неприменимом исключении серой зоны, `realizable=false` и продаже система проверяет `check.excise.ignoreTrueApiMarkRealizable`.
4. При выключенном игнорировании и состоявшейся продаже система направляет пользователя в CSI.
5. При сохранённом `realizable=true` и противоречащем отклонении система применяет `RA-04` и направляет данные в Честный Знак.
6. Доказанное отсутствие результата отделено от ситуации, когда исторический результат просто не найден.

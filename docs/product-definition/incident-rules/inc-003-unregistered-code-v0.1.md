# Правило анализа INC-003 v0.1

**Инцидент:** Продажа товара с КИ, незарегистрированными в ГИС  
**Код True API:** категория `5`, вид `10`, результат `13`  
**Статус:** согласовано Product Manager  
**Основание согласования:** `PM-DEC-048`  
**Связанные артефакты:** [Каталог инцидентов v0.1](../incident-catalog-v0.1.md), [Decision Model v0.1](../decision-model-v0.1.md), [Модель необходимых действий v0.1](../necessary-action-model-v0.1.md), [Схема анализа INC-003](../diagrams/inc-003-analysis-flow-v0.4.png)

## 1. Назначение

Правило определяет разбор продажи кода идентификации, который Честный Знак считает незарегистрированным в ГИС МТ. Полученное отклонение всегда создаёт инцидент, но причина выбирается только по сохранённым фактам конкретной продажи.

## 2. Необходимые данные

- полный КМ и товарная группа;
- дата, время, магазин, касса и кассовый чек;
- факт завершения продажи;
- признак получения онлайн-ответа `responseReceived`;
- сохранённый онлайн-ответ `trueApiValidationResponse`;
- значение `found`: `false` означает, что КИ не найден в ГИС МТ;
- значение `utilised`, чтобы не смешивать отсутствие КИ в ГИС МТ с отсутствием сведений о нанесении;
- ответ ЛМ ЧЗ и признаки офлайн-квитанции (`reqId`, `reqTimestamp`, `inst`, `version`), если использован fallback;
- события проверки Set Mark;
- текущая настройка `check.excise.validateMarkInTrueApi` для товарной группы;
- текущая настройка `check.excise.ignoreTrueApiMarkFound`, разрешающая или запрещающая продажу при `found=false`;
- текущая настройка `check.excise.ignoreTrueApiTimeout` (`Разрешить продажу при отсутствии ответа от ЧЗ`);
- доступный снимок сведений ГИС МТ о КМ на момент операции.

Текущая конфигурация и текущий статус КМ не доказывают их историческое значение в момент продажи.

## 3. Возможные причины и действия

| Ветка | Условие по доступным фактам | Результат | Причина / статус причины | Необходимое действие |
|---|---|---|---|---|
| A | Онлайн ЧЗ ответил `found=false`, но продажа завершена | `RA-01` | Продажу могло разрешить игнорирование результата `found=false` | Проверить `check.excise.ignoreTrueApiMarkFound`; если игнорирование выключено и штатная блокировка должна была сработать, обратиться в поддержку CSI |
| B | Онлайн ЧЗ ответил, но `found=true` либо сохранённый ответ противоречит INC-003 | `RA-04` | Причина расхождения не определена достоверно | Передать в поддержку Честного Знака отклонение, КМ, чек и полный онлайн-ответ |
| C | Онлайн-ответ не получен; ЛМ ЧЗ дал разрешающий результат; продажа завершена | `RA-01`; риск автоштрафа `Нет` | Законный fallback не содержит `found` и не мог выявить отсутствие КИ в ГИС МТ до продажи | Кассовое исправление не требуется; при необходимости отдельно рассмотреть усиленную бизнес-меру — отключение ЛМ ЧЗ с предупреждением, что при недоступности онлайн ЧЗ продажи будут заблокированы |
| D | Ответа нет ни от онлайн ЧЗ, ни от ЛМ ЧЗ; продажа завершена | `RA-01` | Продажа выполнена без разрешающего результата обязательной проверки | В визуализированных настройках проверить, включена ли валидация товарной группы в ЧЗ |
| E | Нет ни онлайн-, ни офлайн-ответа, но текущие настройки уже корректны | `RA-01`; причина не определена достоверно | По текущим настройкам продажа не должна была завершиться | Обратиться в поддержку CSI и приложить чек, КМ и события попыток проверки |
| F | Не сопоставлены КМ/продажа либо нельзя определить канал и результат проверки | `RA-04` | Причина не определена достоверно | Получить полный КМ, чек, `responseReceived`, онлайн-ответ и реквизиты офлайн-квитанции |

Текущая конфигурация становится доказательством причины только при наличии исторического снимка или события на момент продажи. Для ветки `found=false` применяется `check.excise.ignoreTrueApiMarkFound`. Значение `realizable=false` означает отсутствие ввода в оборот и не используется как признак INC-003; настройка `check.excise.ignoreTrueApiMarkRealizable` относится только к этому отдельному признаку.

## 4. Порядок анализа

1. Сопоставить отклонение с продажей по полному КМ.
2. Подтвердить завершение продажи.
3. Определить, был ли получен онлайн-ответ.
4. Если онлайн-ответ есть, проверить `found`: при `false` и состоявшейся продаже проверить `check.excise.ignoreTrueApiMarkFound`; `true` при INC-003 создаёт противоречие данных.
5. Если онлайн-ответа нет, определить, получен ли ответ ЛМ ЧЗ.
6. Разрешающий ответ ЛМ ЧЗ считать законным fallback, который не проверяет `found`.
7. Если нет ответа ни одного канала, проверить в визуализированных настройках, включена ли валидация товарной группы в ЧЗ.
8. При подтверждённой продаже без блокировки установить `RA-01`; при недостаточных или противоречивых данных установить `RA-04`.

## 5. Ограничения v0.1

- Set Mark не исправляет регистрацию КМ в ГИС МТ.
- Онлайн-ответ содержит `found`, а ответ ЛМ ЧЗ — нет; офлайн-ветка не может установить отсутствие КИ в ГИС МТ.
- Отключение ЛМ ЧЗ является усиленной бизнес-мерой: при недоступности онлайн ЧЗ продажа маркированного товара будет заблокирована.
- Текущий статус КМ не заменяет исторический статус.
- Отсутствие регистрации не определяет автоматически виновного участника поставки.
- Риск автоштрафа устанавливается в `Нет`, пока отдельное действующее нормативное правило не подтверждено.

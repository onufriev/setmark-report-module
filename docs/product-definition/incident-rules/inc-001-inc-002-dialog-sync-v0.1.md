# Синхронизация решений по INC-001 и INC-002 v0.1

**Статус:** согласовано Product Manager  
**Дата:** 2026-07-31  
**Ветка:** `review/product-definition-v0.1`

Документ фиксирует итоговые решения, принятые при последовательном разборе инцидентов `INC-001` и `INC-002`. При расхождении с предварительными формулировками общего каталога v0.1 приоритет имеют детальные правила:

- [INC-001 — Повторные продажи у одного продавца более или равно 30 минут](inc-001-repeat-sales-same-seller-v0.1.md);
- [INC-002 — Реализован товар с истекшим сроком годности](inc-002-expired-product-sale-v0.1.md).

## 1. Общие решения модели анализа

1. Необходимое действие автоматически формируется системой после анализа конкретного инцидента.
2. Пользователь не выбирает, не подтверждает и не редактирует сформированное действие.
3. Одинаковые действия могут агрегироваться по нескольким инцидентам.
4. У одного инцидента одна фактическая причина. Если её нельзя определить достоверно, система не заявляет несколько причин как факт, а показывает статус `Причина не определена достоверно` и предусмотренные правилом проверки или действия.
5. Изменение правила не пересчитывает ранее созданные инциденты. Новая версия применяется только к новым инцидентам; версия правила сохраняется для воспроизводимости результата.
6. Текущая конфигурация Set Centrum не доказывает, что такое же значение действовало в момент операции, если историческая версия настройки недоступна.

## 2. INC-001 — итоговая логика

### 2.1. Между продажами найден успешный возврат

- По данным SetRetail нарушение торговой сети не подтверждено.
- Пользователь должен найти чек возврата в ОФД.
- Если чек возврата отсутствует в ОФД — обратиться в техническую поддержку CSI.
- Если чек возврата найден и корректен, но Честный Знак сформировал отклонение — обратиться в техническую поддержку Честного Знака.
- Обращение в поддержку ОФД не назначается.
- Дополнительный поиск ещё одной продажи после возврата в правило v0.1 не входит.

### 2.2. Между продажами нет возврата

Вторая продажа одного КМ считается подтверждённым нарушением. Проверяются причины:

1. Продажи в разных магазинах, а в магазинах установлены отдельные Set Mark Centrum — рекомендовать переход на централизованный Set Mark Centrum.
2. Отключена проверка товарной категории в Set Mark — включить соответствующий параметр `Валидировать…`.
3. Продажа выполнена при недоступности Set Mark, а операция разрешена настройкой — выключить `Разрешать операцию, при недоступности сервера` или применимый аналог для товарной группы.
4. Если ни одна причина не подтверждена — обратиться в техническую поддержку CSI.

Система не предлагает синхронизацию отдельных экземпляров Set Mark Centrum между магазинами: такой возможности нет.

## 3. Законная схема разрешительного режима

Базовая предусмотренная схема проверки маркированного товара:

1. касса сначала выполняет проверку кода маркировки в онлайн-сервисе Честного Знака;
2. если онлайн-сервис недоступен, касса выполняет офлайн-проверку в установленном у ритейлера ЛМ ЧЗ;
3. продажа по разрешающему ответу ЛМ ЧЗ является штатным законным сценарием разрешительного режима;
4. ЛМ ЧЗ проверяет меньше признаков, чем онлайн-сервис, поэтому законность офлайн-процедуры не означает наличие всех данных, доступных онлайн.

Использование ЛМ ЧЗ само по себе не является ошибкой настройки, нарушением процесса или основанием признать инцидент критическим.

## 4. INC-002 — структура ответа и границы ответственности

1. Касса независимо обращается в онлайн-сервис Честного Знака и в Set Mark.
2. Set Mark не является посредником онлайн-проверки и на текущем этапе не контролирует срок годности.
3. ЛМ ЧЗ не возвращает срок годности.
4. Онлайн-сервис Честного Знака в ответе метода `codes/check` возвращает срок годности в поле `expireDate`.
5. Касса сравнивает дату и время проверки со значением `expireDate` и принимает решение о разрешении продажи.

Условие истечения срока:

`дата и время проверки >= expireDate`.

Отсутствующая, пустая, `null` или форматно некорректная дата рассматривается отдельно и не равна подтверждённому истёкшему сроку.

## 5. INC-002 — две ветки

### 5.1. Онлайн ЧЗ передал истёкший срок, но касса продала товар

Результат устанавливается до поиска причины:

- подтверждённое нарушение;
- критическое;
- риск автоштрафа — да.

Причина и необходимое действие определяются проверками:

1. Включён ли параметр `Валидировать…` для товарной группы.
2. `check.excise.ignoreTrueApiMarkExpirationDate` должен иметь значение `false`.
3. Настройка `Разрешать продажу при любом значении даты окончания срока годности`, если она присутствует в версии, должна быть выключена.
4. `check.excise.ignoreTrueApiMarkIncorrectExpirationDate = false` используется для отсутствующего или некорректного срока и не объясняет продажу при корректном истёкшем `expireDate`.
5. Если настройки корректны, но продажа состоялась — обратиться в техническую поддержку CSI.

Найденная причина не отменяет факт нарушения, его критичность или риск автоштрафа.

### 5.2. Онлайн ЧЗ недоступен, ЛМ ЧЗ разрешил продажу

Условия:

- онлайн-ответ не получен из-за отсутствия связи или недоступности сервиса;
- касса получила разрешающий ответ ЛМ ЧЗ;
- в ответе ЛМ ЧЗ отсутствует срок годности;
- позднее Честный Знак зарегистрировал продажу просроченного товара.

Результат:

- подтверждённое нарушение;
- некритическое;
- риск автоштрафа — нет, поскольку касса до продажи не получила явный истёкший срок от онлайн ЧЗ.

Причина:

> Использование ЛМ ЧЗ позволило продолжить продажу без получения `expireDate` от онлайн-сервиса Честного Знака.

Сам сценарий онлайн → ЛМ ЧЗ остаётся законным.

## 6. Усиленная мера для полного исключения риска срока годности

Чтобы гарантированно не продавать товар без полученного онлайн-срока годности, необходимое действие для офлайн-ветки:

> Отключить ЛМ ЧЗ и выполнять проверку маркированных товаров только через онлайн-сервис Честного Знака.

Это действие является не требованием законодательства, а более жёстким бизнес-решением для исключения риска продажи просроченного товара.

Обязательное предупреждение:

> После отключения ЛМ ЧЗ при недоступности онлайн-сервиса Честного Знака продажа маркированных товаров будет заблокирована. Мера исключает риск продажи товара с истёкшим сроком без полученного `expireDate`, но создаёт операционный риск остановки продаж при проблемах связи.

Отключение только параметра `Разрешить продажу при отсутствии ответа от ЧЗ` не считается достаточным действием, если касса может перейти на ЛМ ЧЗ и получить разрешающий ответ без срока годности.

## 7. Известное расхождение общего каталога v0.1

Предварительная строка `INC-002` в `incident-catalog-v0.1.md` была создана до завершения детального разбора и не полностью отражает:

- структуру `codes/check` и поле `expireDate`;
- разделение критической онлайн-ветки и некритической офлайн-ветки;
- законность штатного перехода на ЛМ ЧЗ;
- усиленное действие по отключению ЛМ ЧЗ с обязательным предупреждением об остановке продаж.

До выпуска синхронизированной версии общего каталога источником требований по `INC-002` являются детальное правило и настоящий документ. Реализация не должна использовать устаревшую строку каталога отдельно от этих артефактов.

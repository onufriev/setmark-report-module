# Каталог инцидентов v0.1

**Функция Set Mark:** контроль нарушений
**Версия:** 0.1
**Статус:** предзаполненный рабочий каталог для проверки Product Manager
**Ревью:** вынесено на внешнее согласование в ветке `review/product-definition-v0.1`
**Связанные артефакты:** [Domain Model v0.1](domain-model-v0.1.md), [Decision Model v0.1](decision-model-v0.1.md), [Нормативный реестр v0.1](regulatory-register-v0.1.md)

## 1. Назначение

Каталог определяет, как известные категории отклонений True API рассматриваются новой функцией Set Mark. Каждая запись отклонения создаёт инцидент, даже если она находится вне области ответственности Set Mark, объясняется допустимым сценарием или пока не поддержана правилом анализа.

Каталог v0.1 является базовой версией для дальнейшего развития. Каноническим источником его кодов и названий на этом этапе являются встроенные справочники документа True API v704.0: «Категории отклонений», «Виды отклонений» и «Результаты выявления отклонений» на страницах 1229–1234. Изменения состава инцидентов, правил анализа и рекомендуемых настроек в процессе создания продукта являются штатным версионируемым развитием каталога. В колонке «Вид отклонения Честного знака» допускаются только названия, дословно подтверждённые справочником `ANALYTICAL_VIOLATIONS_NAMES`, выгрузкой «Отклонения» или официальными материалами «Честного знака». Внутренние аналитические сценарии Set Mark не должны выдаваться пользователю за виды отклонений Честного знака.

## 2. Значения полей

| Поле | Значение |
|---|---|
| Область выбытия | Возникло ли отклонение при розничной реализации/выбытии; все такие отклонения входят в область продукта независимо от контура устранения |
| Контур устранения | Система или процесс, где устраняется первопричина: Set Mark, SetRetail, ГИС МТ или внешний бизнес-процесс; допускается несколько контуров |
| Инцидент | Всегда «Да» для полученной записи True API |
| Правило анализа | ID правила Decision Model либо `TBD` |
| Риск автоштрафа | `Да` только по действующему правилу Нормативного реестра при выполнении всех его условий; во всех остальных случаях — `Нет` |
| Регуляторный риск | Может ли повторяемость типа учитываться как индикатор риска |
| Рекомендуемая настройка | Точный путь, процессинг, параметр и целевое значение в актуальной конфигурации магазина в Set Centrum |
| Статус строки | Степень готовности записи каталога |

## 5. Правила ведения каталога

1. Официальный код и название берутся только из подтверждённого источника True API.
2. Риск автоштрафа устанавливается только при подтверждённом нормативном основании.
3. Новый неизвестный тип не отбрасывается и получает `RA-05`.
4. Для каждого поддерживаемого типа должны быть определены необходимые данные и хотя бы одно правило анализа.
5. Превышение накопленного порога делает критическим агрегированный показатель магазина, а не отдельные инциденты.
6. Рекомендуемая настройка хранится отдельно от текущей настройки магазина и должна иметь версию.
7. Текущая конфигурация не доказывает историческое значение настройки в момент продажи.
8. При расхождении краткой строки каталога и согласованного подробного правила приоритет имеет подробное правило.

## 6. Явные ограничения v0.1

- Полный официальный перечень отклонений ещё сопоставляется с каталогом.
- Не определены все нормативные основания автоштрафов по датам и товарным группам.
- Кассовые логи и автоматическая проверка чеков в ОФД не входят в v0.1, если это прямо указано в подробном правиле.

## 7. Критерий готовности версии 1.0

Каталог готов к версии 1.0, когда перенесён полный официальный перечень, по каждой строке подтверждены область, источники, правило анализа, нормативная критичность и рекомендуемые действия.

# Инструкция по визуальному прототипу

## 1. Состав прототипа
Источник UI: `COMPONENT_LIBRARY`. Источник приложения: `GENERATED_PROTOTYPE`. Материализованный источник: `Сгенерированный прототип на основе @crystalservice/csi_ui и актуального frontend Set Mark`. Реальный entryPoint: `visual-prototype/app/index.html`.

Оболочка и продуктовая навигация сверяются с Set Centrum `/products/search` и паттерном Set Loyalty. Визуализация Журнала нарушений и автономно встроенные логотипы получены из переданного `setmark-control-prototype.html`; его устаревшая бизнес-логика лицензирования не переносится.

## 2. Предварительные требования
- Python 3.10+ на Windows, macOS или Linux.
- Свободный порт 8000.

## 3. Запуск
Из корня проекта: `python -m http.server 8000 --directory visual-prototype`. Открыть `http://localhost:8000/app/index.html`.

## 4. Демонстрационные данные
Используются локальные статические данные внутри `visual-prototype/`.

## 5. Проверка основного сценария
1. Обзор сети: `#overview`
2. Журнал нарушений, доступный Администратору системы: `#journal`
3. Критические инциденты с риском автоштрафа: `#priority`
4. Список инцидентов и CSV из 23 колонок: `#incidents`
5. Карточка инцидента: `#incident/INC-10621`
6. Аналитика и выгрузка: `#analytics`
7. Настройки и подключение Честного знака с ЭЦП: `#settings`

В верхней панели переключаются демонстрационные сценарии: действующая лицензия, лицензионное несоответствие, льготный период, отсутствие или окончание лицензии, неизвестный статус с историей и без неё, отсутствие права ЖН и страна не `RU`.

Проверка: `python tools/validate_visual_prototype.py --phase VISUAL_PROTOTYPE`.

## 6. Устранение проблем
Проверьте entryPoint, относительные ссылки и отсутствие Storybook-зависимостей.

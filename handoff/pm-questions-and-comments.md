1. Ручной процесс получения данных от TrueAPI

Отсутствует описание сценария ручного получения данных об отклонениях от True API.
В документации True API описан процесс получения данных, как процесс из четырех шагов:
- отправка запроса на формирование выгрузки с параметрами, например, диапазон дат
- проверка готовности выполнения до появления статуса
- запрос списка файлов и их статус
- скачивание файлов
  Далее необходимо сохранить/обновить данные в БД.
  Таким образом это асинхронный процесс, который требует мониторинга выполнения.
  Нет возможности по нажатие на кнопку пользователем сразу выполнить результат и оповестить OK, NOK.
  К тому же у True API для каждого метода есть ограничения по частоте вызовов.

Для реализации такой интеграции будет создана очередь заданий для скачивания чего-либо из TrueAPI, т.к. подход для разных типов данных там общий и эта общая реализация может быть полезной в будущем.
Т.е. при ручном обмене пользователь создаёт задание, указывает за какой период ему нужны отклонения.
Далее необходимо отслеживать процесс выполнения задания. Для этого нужен UI и макеты.
Процесс не может быть вечным и будет настраиваемое ограничение по времени его выполнения.

Также возникают такие вопросы:
- Может ли один или разные пользователи создавать задания для скачивания отклонений с разными, похожими или пересекающимися периодами ? Какое поведение системы при таких сценариях ожидается?
- Если на одном из этапов выполнения задания произойдет ошибка, что будет пользователь, как его оповестить?


1.1. В загружаемых данных об отклонениях нет ссылок на справочники "Категории отклонений", "Виды отклонений", "Результаты выявления отклонений",
поля содержат не коды из этих справочников, а наименования. \
Загрузка/обновление справочников "Категории отклонений", "Виды отклонений", "Результаты выявления отклонений" 
могут быть полезны при указании параметров когда выполняется заказ на выгрузку отклонений (8.3.15), т.к.
в аргументах могут передаваться именно коды из этих справочников. \
> Вопрос: предполагается ли загрузка отклонений с использованием фильтров по категориям, видам, результатам?
Если да, то синхронизация справочников, как и хранение в БД понадобится, иначе - нет.

2. В спецификации True API отсутствует информация о типах полей в выгружаемой информации об отклонениях.
Только для двух полей: "Дата и время регистрации отклонения" и "Дата и время выполнения операции, в результате которой было выявлено отклонение" можно точно сказать, 
что там дата-время. Для остальных полей можно только догадаться по примерам, что там String, Integer, Decimal. 

> Информация нужна, чтобы создать оптимальную и правильную схему БД для хранения отклонений необходимо знать информацию о типах полей.

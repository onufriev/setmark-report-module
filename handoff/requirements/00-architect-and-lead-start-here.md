# Начало работы архитектора и лида

## Что создаётся

Мониторинг маркировки — дополнительная функция Set Mark для централизованного контроля
официальных отклонений Честного знака. В MVP интерфейс работает внутри текущего
Журнала нарушений и не меняет его существующие функции.

Факт отклонения приходит из ЛК Честного знака через True API. Журнал нарушений,
чек, результаты проверок и исторические настройки только дополняют карточку и помогают
восстановить кассовый контекст.

## Этапы поставки

1. **Контроль отклонений Честного знака.** Подключение ЭЦП по ИНН, ручное получение
   данных, Обзор, Инциденты, исходная карточка ЧЗ, поиск, фильтры, группировки и
   настройка критичности. Это самостоятельный пригодный к эксплуатации выпуск.
2. **Обогащённый разбор инцидента.** Сопоставление с Журналом нарушений, чеком,
   параллельными проверками и историческими настройками. Этот выпуск завершает MVP.
3. **После MVP.** Автоматическое объяснение причин и рекомендации, Необходимые
   действия, отдельная Аналитика, CSV/PDF, уведомления, интерфейс SetCentrum и
   демонстрационный режим без установленного Set Mark.

Каждый из первых двух этапов принимается отдельно на реальном подключении ЛК ЧЗ,
не содержит заглушек в доступных функциях и может использоваться клиентом сразу после
выпуска.

## Правила, которые нельзя потерять

- мониторинг работает только при `setmark.country=RU`;
- одно релевантное отклонение True API создаёт ровно один инцидент;
- марка сопоставляется по вхождению, а окно ±5 минут считается точным совпадением;
- онлайн ЧЗ и Set Mark проверяются параллельно, после чего касса принимает решение
  и отдельно фиксирует фактическое действие;
- в MVP нет новой ролевой модели: действует доступ текущего Журнала нарушений;
- синтетические ответы True API не заменяют приёмку на реальных данных;
- мониторинг не добавляет синхронных вызовов в кассовый процесс.

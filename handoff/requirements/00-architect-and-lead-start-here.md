# Handoff для архитектора, лида и разработчика

Этот handoff — человекочитаемое производное утверждённых требований функции мониторинга отклонений маркировки внутри Set Mark. Он нужен для передачи целостного контекста команде разработки.

## Как читать

Каноническими источниками остаются файлы в `requirements/`, `product/requirements-baseline.json` и реестры `product/`. Этот handoff предназначен только для людей: по нему нельзя изменять или проверять полноту канонических требований. Полные формулировки, проверки и исключения находятся в исходных файлах.

Рабочий прототип пропущен отдельным решением Product Manager. Поэтому production-стек, production API, источник данных рабочего прототипа и материалы прототипирования здесь не фиксируются; производственные технические решения остаются зоной ответственности команды разработки, если канонические требования не устанавливают ограничение.

## Главная продуктовая задача

Ответственный сотрудник должен увидеть нарушение маркировки, понять, где и почему оно возникло, оценить регуляторный риск и перейти к необходимому изменению в соответствующем Контуре устранения. Сначала обрабатываются критические инциденты с возможным автоштрафом; при их отсутствии приоритет получают действия, связанные с наибольшим числом инцидентов.

Трассировка: `REQ-GS-001`, `REQ-GS-002`, `REQ-DEC-089`, `REQ-DEC-042`.

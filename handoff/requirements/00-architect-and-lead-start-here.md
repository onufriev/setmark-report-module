# Мониторинг и анализ нарушений Set Mark — старт для архитектора и лида

Этот каталог — единое описание MVP для архитектурного решения и планирования
разработки, предназначенное только для человека. Начните с этого файла, затем последовательно прочитайте документы
`01`–`08`. Канонические требования нужны только для проверки конкретной детали;
ссылка на них приведена в `08-traceability.md`.

Product Compiler и другие ИИ не используют файлы этого каталога как источник фактов,
вход для проверки полноты или основание для изменения канонических требований.

## Что нужно создать

Новая функция **«Мониторинг и анализ нарушений»** внутри существующего Set Mark.
Она получает зарегистрированные в «Честном знаке» отклонения розничной реализации
и выбытия, сопоставляет их с данными Set Mark, создаёт и анализирует инциденты.
Пользователь видит, что произошло, где возникло нарушение, насколько оно рискованно
и какое действие может предотвратить повторение.

Функция не является отдельным продуктом или автономным модулем. Она поставляется,
обновляется, аутентифицируется и лицензируется вместе с Set Mark. Пользовательский
интерфейс находится в оболочке SetCentrum; интеграция, обработка и данные принадлежат
Set Mark.

## Что особенно важно для решения

- MVP применяется только к организациям с нормализованной страной `RU`.
- Данные True API в MVP получает вручную сотрудник с рабочей УКЭП и привилегией
  настройки подключения. Автоматический запуск — будущая возможность.
- Сбой функции, её обработка и аналитика не должны влиять на продажи и проверку
  кодов на кассах.
- Один исходный факт отклонения должен приводить максимум к одному инциденту;
  повторная доставка не создаёт дубликат.
- Сырые события и обязательство их обработать сохраняются до завершения обработки;
  при временном сбое обработка возобновляется автоматически.
- В MVP нет блокировки продажи, автоматического исправления, управления задачами,
  назначения ответственных и мобильного приложения.

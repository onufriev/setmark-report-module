# 5. Границы MVP, контекст системы и ответственность

## Входит и не входит

В MVP входит аналитический контур мониторинга розничных отклонений: приём данных, корреляция, инциденты, Дашборд, список, карточка, аналитика, CSV/PDF, рекомендации, уведомления и настройки. Из MVP исключены производственные и логистические процессы, realtime-блокировка, автоматическое исправление, автообращения, ML, мобильное приложение и управление исполнением задач.

Трассировка: `REQ-DEC-003`, `REQ-DEC-034`, `REQ-GS-003`, `REQ-GS-004`.

## Контекст обмена

Set Mark предоставляет оболочку, аутентификацию, навигацию, права и сохранённые данные. SetCentrum определяет организацию, страну и действует как контур аутентификации/привилегий. True API и «Честный знак» являются источниками отклонений в подтверждённой модели обмена; события Set Mark и контекст разрешительного режима участвуют в корреляции. Кассы, SCO, сканеры и другое оборудование не управляются модулем напрямую.

Функция отвечает за представление, анализ, приоритизацию и объяснение данных; исправление настроек/данных, управление задачами и контроль исполнения остаются за клиентом и соответствующими внешними контурами. Прямые интеграции с кассами, Set Retail, Set Centrum и True API не требуются, если данные уже поступают и сохраняются существующим Set Mark.

Трассировка: `REQ-PC-002`, `REQ-FR-007`, `REQ-INT-001`–`REQ-INT-003`, `REQ-DEC-019`, `REQ-DEC-032`, `REQ-DEC-075`, `REQ-DEC-096`, `REQ-DEC-099`, `REQ-DEC-012`.

## Ответственность команды разработки

Production-архитектура, стек, контракты API, хранилище, развёртывание, резервирование и конкретная реализация не выбраны требованиями и передаются команде разработки. При этом команда обязана сохранить зафиксированное поведение, ограничения, границы ответственности, правила доступа, целостность событий, идемпотентность и видимость деградации.

Трассировка: `REQ-DEC-013`, `REQ-DEC-014`, `REQ-DEC-078`, `REQ-DEC-081`, `REQ-DEC-087`.

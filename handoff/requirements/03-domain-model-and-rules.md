# 03. Предметная модель, доступ и правила

## Основные объекты

| Объект | Смысл для модуля |
|---|---|
| Отклонение | Исходный факт из True API. Сохраняются исходные наименования, полный raw snapshot и версия справочника. |
| Инцидент | Единственный результат обработки одного отклонения; содержит исходные данные, результат анализа, объяснение, риск и рекомендацию. |
| Операция и код маркировки | Данные Set Mark для корреляции. Поиск должен находить инцидент по полному коду маркировки. |
| Необходимое действие | Системная рекомендация, группирующая связанные инциденты; только чтение, без задач и статусов. |
| Контур устранения | Внешний контур или место, где пользователь должен внести изменение. |
| SyncRun | Ручной запуск получения данных True API; повторная авторизация продолжает тот же запуск. |

## Состояния инцидента и данных

Инцидент проходит состояния **«Получен» → «Анализируется» → «Анализ завершён»**
либо **«Ошибка обработки»**. Пока анализ идёт, итог и рекомендации не показываются.

При неполных данных применяется `RA-04` с перечнем недостающего. Неизвестный тип
отклонения получает `RA-05`; система не должна выдумывать результат. Пользователь
видит понятное наименование результата, а не технический код `RA-*`.

Блок состояния данных показывает только:

1. успешность последнего обращения к «Честному знаку» и его дату/время;
2. наличие связи с SetCentrum.

## Доступ и лицензия

Доступ проверяется в два уровня: сначала право просмотра Журнала нарушений, затем
отдельная привилегия конкретной операции. Без базового права нельзя раскрывать даже
количество или идентификаторы объектов.

Отдельные привилегии покрывают обзор/аналитику, детали, поиск/фильтры, CSV,
уведомления, подключение True API, получателей и срок хранения. Административная
привилегия всегда предполагает базовое право просмотра Журнала.

При действующей лицензии доступ полный. Несоответствие лицензии или льготный период
дают полный доступ с предупреждением. При отсутствии лицензии, завершённом льготном
периоде или неизвестном статусе без истории доступен усечённый Обзор; журнал,
экспорт, массовый поиск и уведомления запрещены, а в настройках остаётся запуск
подключения ЭЦП. Получение и хранение данных для RU-клиента не прекращается только
из-за лицензионного состояния.

## Бизнес-правила верхнего уровня

- Корреляция использует код маркировки, время и доступные данные Журнала нарушений;
  отсутствие необходимых сведений должно быть явно показано.
- Повторная доставка не создаёт второй инцидент.
- Версия справочника и правил должна быть сохранена с результатом анализа.
- Потенциальный штраф — показатель оценки риска; для накопительного состава он
  рассчитывается один раз на нормативный объект и период, не умножаясь на связанные
  инциденты.
- Действия, предотвращающие критические инциденты, всегда выше остальных; без
  критичных инцидентов приоритет определяется количеством предотвращаемых случаев.

Детальные ветки анализа конкретных видов инцидентов находятся в канонических
правилах; их не следует заменять новой интерпретацией в архитектуре.

**Трассировка:** `REQ-DEC-006`, `REQ-BO-001`–`003`, `REQ-DEC-008`, `REQ-DEC-073`,
`REQ-DEC-083`, `REQ-DEC-009`, `REQ-DEC-038`, `REQ-BR-001`–`003`, `REQ-DEC-053`.

# 3. Системные и технические требования

## Системная роль функции

Функция работает внутри Set Mark и наследует его аутентификацию, доступ к объектам и жизненный цикл. Отдельные установка, запуск, обновление, лицензирование, инфраструктура, SLA и аппаратная часть не требуются. Функция не должна влиять на продажи и проверку кодов при собственной недоступности.

Трассировка: `REQ-FR-007`, `REQ-DEC-019`, `REQ-DEC-032`, `REQ-DEC-075`, `REQ-DEC-010`.

## Сущности и правила

Ключевые сущности — организация/сеть, магазин, касса, товарная группа, инцидент отклонения, исходное событие, код маркировки, тип нарушения, результат проверки, регуляторный риск, потенциальный штраф, необходимое действие и Контур устранения. Один исходный идентификатор отклонения образует один инцидент; повторная доставка не создаёт дубликат. Инцидент хранит исходный снимок и системные состояния обработки.

Корреляция выполняется по полному коду маркировки и согласованным идентификаторам событий Set Mark/SetRetail. Правила различают критичность, автоштраф, индикатор риска, допустимый возврат, неизвестный тип, неполные и устаревшие данные. Накопительный потенциальный штраф считается по утверждённым составам без двойного учёта; он показывается в интерфейсе, но не в CSV.

Результат проверки должен быть объяснимым для пользователя: технические коды `RA-*` не являются пользовательским объяснением. Изменения, необходимые для устранения, выполняются вне функции в соответствующем Контуре устранения; функция не создаёт и не закрывает задачи автоматически.

Трассировка: `REQ-BO-001`, `REQ-BO-002`, `REQ-BO-003`, `REQ-DEC-002`, `REQ-DEC-006`, `REQ-DEC-035`, `REQ-DEC-036`, `REQ-DEC-046`–`REQ-DEC-067`, `REQ-BR-001`–`REQ-BR-003`.

## Доступ и ограничения реализации

Минимальная модель привилегий включает администратора системы и аналитика по работе с маркировкой; роли являются наборами привилегий и управляются существующим Set Centrum. Управление ролями и привилегиями в функции не создаётся. Доступ ограничивается разрешёнными объектами.

Визуальный прототип запускался локально в браузере, включая телефонный браузер, без установки в Set Mark и без реальных интеграций/backend. Для production конкретные архитектура, фреймворк, API и хранилище не предопределены каноническими требованиями.

Трассировка: `REQ-DEC-008`, `REQ-DEC-073`, `REQ-DEC-074`, `REQ-DEC-076`, `REQ-DEC-084`, `REQ-DEC-011`, `REQ-DEC-013`, `REQ-DEC-014`, `REQ-DEC-078`, `REQ-DEC-081`, `REQ-DEC-087`.

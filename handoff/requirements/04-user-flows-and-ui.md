# 04. Пользовательские потоки и поведение интерфейса

## Основной путь: критический инцидент

1. Пользователь открывает Set Mark в оболочке SetCentrum и выбирает период.
2. На Обзоре сразу видит, есть ли критические инциденты и какие объекты имеют
   наибольший риск.
3. Открывает необходимое действие или агрегат; переход переносит период и активные
   фильтры, а число в источнике совпадает с числом открытых инцидентов.
4. В карточке понимает, что произошло, почему получен результат, риск, потенциальный
   штраф, Контур устранения и рекомендацию.
5. Выполняет изменение вне функции; сама функция задачу не создаёт и не контролирует.

## Регулярный путь

Когда критических инцидентов нет, пользователь видит действия, отсортированные по
количеству связанных инцидентов. Он открывает действие, исследует составляющие его
инциденты через фильтры и аналитику и переходит к соответствующему Контуру устранения.

## Рабочие экраны и действия

- **Обзор:** период, два сигнала состояния данных, показатели, критичные объекты,
  топ-5 действий и распределение по типам. Агрегаты кликабельны.
- **Список инцидентов:** фильтры, поиск по штрихкоду, артикулу и полному коду;
  несколько значений через запятую объединяются по «ИЛИ»; возможен множественный
  выбор магазинов.
- **Карточка:** исходные данные, объяснение, риск, потенциальный штраф, Контур
  устранения, рекомендация, PDF одного инцидента.
- **Аналитика:** динамика, пороги и распределение по типам; до 14 дней группировка
  по дням, при большем периоде — по неделям.
- **Настройки:** подключение True API, получатели уведомлений, срок хранения.

CSV экспортирует только текущую выборку в утверждённом наборе из 23 колонок.
Ежедневное уведомление ведёт к соответствующему инциденту или выборке в Set Mark.

## Пустые, ошибочные и недоступные состояния

- нет нарушений — «Нарушения не обнаружены»;
- фильтры не дали результата — объяснение и действие «Сбросить фильтры»;
- загрузка — индикатор, без выдачи старых данных за актуальные;
- устаревшие/частичные данные — доступный результат с явным ограничением;
- ошибка обработки — понятное описание и идентификатор инцидента;
- недостаточно прав — сообщение без раскрытия объекта;
- ошибка подключения — администратор видит проблемное подключение и причину.

Интерфейс использует существующий визуальный язык Set Mark и паттерны CSI UI. Он
адаптивен, доступен с клавиатуры и не требует отдельного мобильного приложения.

**Трассировка:** `REQ-FR-001`–`007`, `REQ-DEC-033`, `REQ-DEC-040`–`042`,
`REQ-DEC-024`, `REQ-DEC-009`, `REQ-DEC-015`, `REQ-DEC-016`, `REQ-DEC-078`.

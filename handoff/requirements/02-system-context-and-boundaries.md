# 02. Контекст системы и границы ответственности

## Контур MVP

```text
Пользователь
    │ интерфейс и навигация
    ▼
SetCentrum ─────────────► Set Mark: права, данные, обработка, аналитика
                                │
                     ┌──────────┼───────────┐
                     ▼          ▼           ▼
                True API   Журнал      Данные кассовых
                Честного   нарушений   проверок и операций
                знака      Set Mark
```

## Границы компонентов

| Область | Обязанность |
|---|---|
| SetCentrum | Общая оболочка, навигация, действующая аутентификация и управление ролями. |
| Set Mark | Новая интеграция True API, владение данными, создание и анализ инцидентов, права, аналитика и контракты для UI. |
| Кассовое ПО | Как и сейчас, напрямую работает с онлайн «Честным знаком» и ЛМ ЧЗ; передаёт Set Mark результаты уже выполненных проверок. |
| True API | Внешний источник зарегистрированных отклонений по ИНН. |

UI не должен напрямую интегрироваться с кассами, SetRetail или True API. Размещение
экрана в SetCentrum не переносит туда владение данными или интеграционную логику.

## Сквозной системный поток

1. Уполномоченный пользователь запускает получение отклонений для доступного ИНН.
2. Set Mark сохраняет исходный снимок данных и долговечное обязательство создать
   инцидент.
3. Идемпотентная обработка создаёт один инцидент, сопоставляет его с доступными
   операциями, проверками и настройками Set Mark.
4. По версии правил формируются понятный результат, объяснение, риск, потенциальный
   штраф, Контур устранения и рекомендация.
5. Результат появляется на обзоре, в аналитике, списке, CSV и уведомлениях.
6. При ошибке исходное событие не теряется, а обработка повторяется после
   восстановления.

## Что команда должна решить сама

Команда определяет границы сервисов и модулей, хранилища, очереди, механизмы
идемпотентности, API-контракты, способ работы с УКЭП, наблюдаемость и развёртывание.
Выбранное решение должно сохранять указанные продуктовые границы и не создавать
отдельный продукт, отдельную аутентификацию, установку или аппаратную часть.

**Трассировка:** `REQ-DEC-019`, `REQ-DEC-032`, `REQ-DEC-075`, `REQ-INT-001`–`003`,
`REQ-DEC-021`.

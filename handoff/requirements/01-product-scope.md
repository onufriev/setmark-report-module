# 01. Продукт и границы MVP

## Проблема и результат

Ответственные сотрудники торговой сети поздно узнают об отклонениях маркировки:
данные разрознены, причина и место возникновения неочевидны. Модуль должен
сократить задержку между отклонением и его обнаружением, объяснить причину,
показать регуляторный риск и рекомендовать компенсирующее действие.

Это не гарантия отсутствия штрафов или проверок: функция помогает клиенту принять
действие, но не выполняет его автоматически.

## Два режима работы

**Критический.** Пользователь сразу видит инциденты, для которых возможен
автоматический штраф, и связанные с ними необходимые действия.

**Регулярный.** Если критичных инцидентов нет, пользователь видит действия,
предотвращающие наибольшее количество повторных инцидентов, и исследует их через
список, карточки и аналитику.

Индикатор риска не равен доказанному нарушению и не должен маркироваться как
основание для автоштрафа. Такой риск показывается только для применимых типов
инцидентов.

## В MVP входит

- получение отклонений розничной реализации и выбытия через True API;
- сопоставление с данными Set Mark и SetRetail по полному коду маркировки;
- обзор сети: показатели, критичные объекты, типы нарушений, состояние данных;
- список, поиск, фильтры, карточка инцидента и переходы из агрегатов к выборке;
- объяснение результата, критичность, потенциальный штраф, Контур устранения и
  рекомендация;
- необходимые действия: топ-5 на обзоре и полный перечень;
- аналитика накопления и пороговых показателей;
- CSV текущей выборки и PDF одного инцидента;
- ежедневное уведомление о критичных нарушениях;
- настройки подключения, получателей уведомлений и срока хранения.

## В MVP не входит

- производство, импорт, логистика, ввод в оборот и иные процессы вне розничного
  выбытия;
- блокирование продажи в реальном времени;
- автоматическое исправление настроек и данных, создание обращений в ГИС МТ;
- ML-прогноз, мобильное приложение, пересчёт старых инцидентов при смене правил;
- новые каналы или периодичность уведомлений сверх ежедневного сценария;
- назначение ответственных, задачи, статусы и контроль выполнения действий.

## Применимость и коммерческая граница

Мониторинг доступен только для `RU`. Для другой страны не должны существовать его
навигация, страницы, API, подключение ЭЦП, сбор, обработка и хранение данных;
остальные возможности Set Mark остаются без изменений.

Функция входит в коробочное решение Set Mark и отдельно не лицензируется. Для
RU-клиента SetRetail без Set Mark допускается ограниченный Обзор и Аналитика после
подключения ЭЦП; полные детали и журнал определяются лицензионным режимом.

**Трассировка:** `REQ-PC-001`, `REQ-PC-002`, `REQ-GS-001`–`004`, `REQ-DEC-003`,
`REQ-DEC-034`, `REQ-DEC-052`, `REQ-SO-001`, `REQ-DEC-089`.

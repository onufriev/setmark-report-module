# Данные, интеграции и системная обработка

## True API

Set Mark реализует новую интеграцию с методом True API 8.3.15.1 «Выгрузка сведений об
отклонениях». Подключение настраивается отдельно для каждого ИНН и считается рабочим
после успешной авторизации с УКЭП и проверки соединения. Корректный пустой ответ также
подтверждает подключение.

В MVP получение запускается вручную пользователем с рабочей УКЭП и продолжается в
фоне. Пользователь выбирает один из периодов: с последней успешной синхронизации
либо последние 1, 7, 30 или 90 календарных дней, включая текущий. При первом запуске
доступны фиксированные варианты, в том числе 7 дней; обязательной загрузки за 90
дней нет. Произвольный диапазон не задаётся. Для одного ИНН одновременно существует
только один активный запуск, а при повторной попытке интерфейс показывает уже
выполняющееся задание. По каждому ИНН видны текущее состояние и результат последнего
обращения с временем; отдельная история запусков в MVP не нужна. Автоматическая
периодика возможна только после появления допустимого способа круглосуточной подписи
или авторизации.

## Источники обогащения

- Журнал нарушений Set Mark передаёт зафиксированное событие и результат своей
  проверки;
- кассовые данные содержат чек, продажу, возврат или отмену;
- касса передаёт раздельные результаты онлайн ЧЗ, Set Mark и ЛМ ЧЗ;
- снимок настроек передаётся с хэшем, позволяющим восстановить значения на момент
  операции;
- исходные наименования вида и результата из `VIOLATIONS` сохраняются без
  сопоставления с кодами в MVP; справочник потребуется на этапе анализа.

## Состав исходного отклонения

Обязательно хранятся строковый номер отклонения без требования формата UUID, исходные
наименования вида и результата и вся строка `VIOLATIONS` со всеми колонками и привязкой
к загрузке. Коды категории, вида и результата в MVP не вычисляются. Исходные значения
дат сохраняются без изменения; при интерпретации значений без зоны в MVP действует
продуктовое допущение `Europe/Moscow`, не подтверждённое источником. Неиспользуемые
колонки остаются исходными строками, а используемые поля типизируются по их назначению.
Полный код маркировки внутренних систем хранится отдельно и не подменяет снимок ЧЗ.

## Обработка

При получении выполняются валидация контракта, фильтрация кассовых видов,
идемпотентное сохранение и постановка корреляции в долговечную очередь. Повторная
доставка безопасна. Автоматические повторы временных ошибок имеют конечный предел;
после его исчерпания показывается понятная окончательная ошибка. Ожидание новой
авторизации и квоты остаётся отдельными состояниями.

Период выгрузки относится к дате регистрации отклонения, а не к дате операции.
Режим «с последней успешной синхронизации» повторно включает календарный день
последнего успеха и заканчивается текущим днём; дубли исключаются при импорте.
Это принятое PM правило подлежит проверке на реальном API. Выгрузки и квоты разных
ИНН рассматриваются независимо: ожидание по одному ИНН не блокирует другой.
Срок хранения составляет 90 календарных дней и может быть уменьшен существующей
конфигурацией.
Удаление считается окончательным, восстановление из интерфейса не предусмотрено.

## Обработка следующего этапа

После сбора и сопоставления зафиксированная версия правила формирует внутренний
результат RA-01–RA-05, пользовательское объяснение, потенциальный штраф, Контур
устранения и рекомендацию. Результат доступен карточке, Необходимым действиям,
Аналитике, экспортам и уведомлениям. Повторная обработка остаётся идемпотентной, а
версия правила и исходные факты позволяют воспроизвести вывод.

## Email-дайджест следующего этапа

Один раз в сутки в 09:00 по часовому поясу SetCentrum система формирует дайджест новых
критичных отклонений за предыдущий календарный день. Используется SMTP-сервис,
настроенный в SetCentrum. Получателей настраивает пользователь с соответствующей
привилегией; получение письма отдельной роли не создаёт.

Письмо содержит общее количество, распределение по видам, магазины с наибольшим
числом отклонений и ссылку на совпадающую выборку Инцидентов. Полные коды маркировки,
строки отдельных инцидентов и детали карточек в письмо не включаются. Если новых
критичных отклонений нет, письмо не отправляется и это не ошибка. При временной ошибке
доставки выполняются автоматические повторные попытки; состояние, время и понятная
причина последней ошибки показываются в настройках, история сохраняется. В усечённом
режиме настройка и отправка уведомлений недоступны.

## Реальные данные и безопасность

Полная приёмка требует реального ЛК ЧЗ, рабочей ЭЦП, минимум одного ИНН, успешного
вызова True API, хотя бы одного релевантного отклонения и доступных источников
обогащения минимум для одного случая. Отсутствие редкого вида не блокирует приёмку.

ЭЦП, закрытые ключи, токены, исходные клиентские выгрузки и полные производственные
коды маркировки не сохраняются в Git. Испытания проходят в защищённом контуре;
доступы предоставляет владелец организации, а Product Manager координирует подготовку.

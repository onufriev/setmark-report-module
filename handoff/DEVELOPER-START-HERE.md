## Важные рамки реализации

- MVP применяется для организаций с установленной страной `RU`; остальные разделы Set Mark не должны быть нарушены.
- Рабочий прототип не является частью передачи. Его пропуск не означает готовность промышленный кода.
- Конкретный технологический стек, промышленный архитектура, API-контракты и источник промышленный данных выбираются и фиксируются командой разработки.
- Визуальный прототип показывает ожидаемый пользовательский путь и визуальный язык, но не заменяет функциональные и эксплуатационные требования.

## Результат

Реализация должна удовлетворять требованиям, сценариям и критериям приёмки из этого каталога и сохранять поведение существующей платформы Set Mark вне описанного MVP.
